# Astraへの追加依頼：アプリ全体のUI/UX評価

前のレビューの続きとして、VHSlide 0.43.1の「アプリ全体としてのUI/UX」を評価してください。直近アップデートの出来栄えや、個別の不具合の列挙を中心としたレビューではありません。既に渡したZIPにはsrc・server・cloudflare・testsを含む全体のソースがあります。既存報告は破棄せず、全体評価の中へ位置づけてください。

## 今回の成果物の中心

まず、次の4点を示してください。優先する不具合の一覧だけで結論にしないでください。

1. **全体像と調査範囲**：画面・主要機能・利用状態を一覧化し、どこを実操作したか、コードだけ読んだか、未確認かを明記する。ユーザーが一連の作業をどう進めるアプリなのかを図示する。
2. **製品全体の評価**：初見で理解できるか、目的の操作を発見できるか、操作や言葉に一貫性があるか、現在地と選択状態が分かるか、手順や情報量が過剰でないか、誤操作から回復できるかを評価する。機能が存在することやテストの成功とは区別する。
3. **情報設計・操作体系の改善案**：何をどの画面・メニュー・ツールバーに置き、何を直接操作にし、何を常時見せ／必要時に見せるべきかを、全体として整合する構成にまとめる。現在の画面構成を正解と仮定しない。
4. **実装へつながる改善順**：個別の修正で済むものと、画面構成・共通操作から見直すものを分ける。影響する画面・権限・保存・本人Undo・2次元構造への注意を添える。

## 抜けなく評価する範囲

- 最初に開く／作品を作る・開く／端末とクラウドの違い。
- 全体マップ、行・列の意味、追加・移動・並べ替え・複製・削除、見出しと番号。
- マップと編集の往復、ピンチ、ズーム、現在地、サムネイル、行番号ジャンプ、行の連動。
- 文字・写真・表・図形・線・図解・グラフ・グループ・リンクの挿入から編集完了まで。
- 単体・複数・グループ内・文字範囲・セル範囲の選択、編集と移動の競合、設定欄。
- フィルタ、自分の担当、シート、比較、PDF、発表準備・開始・終了、ルート、発表中の2次元移動。
- クラウド作品一覧、共有相手の追加・割当、ホストと参加者の違い、参加待ち・承認、権限外操作、付箋。
- 自動保存・手動保存・JSON・完全バックアップ・履歴・ごみ箱・復旧の理解、失敗時の案内。
- 画面サイズ、情報密度、文字、コントラスト、操作対象の大きさ、キーボード、マウス・タッチ・タッチパッド、動きと待ち時間。

初見の児童、繰り返し使う生徒、授業を準備・運営する教師を区別してください。ログイン前・ホスト・承認待ち・閲覧のみ・担当範囲あり・通信切断・復旧中など、状態による違いも見てください。400枚サンプルなどで作品が増えた場合を確認し、少数ページの画面だけで評価を終えないでください。

## 既存の指摘の扱い

前報告の「フィルタと発表」「未作成の担当行」「JSON読込とUndo案内」、ピンチ復帰・Undoの試験失敗は、製品全体のどの体験を妨げるかに位置づけてください。ただし、この指摘だけから全体評価を組み立てないでください。再現が安定しない不具合、コード上の仕様、UX上の誤解、試験条件の問題は分けてください。要約だけを根拠に確認済みとしないでください。

各主要判断にファイル・関数・実際の行番号、操作手順、可能なら画面証拠を付けてください。主観的な好み、UX上の仮説、実動作の事実を区別してください。実端末や児童の操作を観察できない場合は、ヒューリスティック評価・代替環境として明記してください。

## 実施条件

レビューのみです。ソース・設定・依存関係・バージョン・実作品の変更、実装、リファクタリング、コミット／push、デプロイは行わないでください。通常の自動デプロイ方針より、このレビューの禁止を優先します。共有された本番ルームを開かず、本番へのログイン・参加申請・書き込みも行わないでください。独立したローカルの作品・テストサーバーで確認してください。

既存報告書は上書きせず、`docs/astra-whole-application-uiux-review.md`へ保存してください。既存なら別名にしてください。
