## 維持する要望・運用

今回の引き継ぎ時にも `npm test`（アプリ173件／Node18件）、`npm run build`、`npm run cf:check` を再実行し成功。ビルドの既存サイズ警告あり。E2E全体は今回再実行していない。ソース・文書・試験証拠の保存対象に対し秘密鍵形式、GitHubトークン形式、環境の認証トークン値との一致を走査し、検出なし。認証の実機確認を意味するものではない。

- 通常の実装は必要な検証、Cloudflare本番デプロイ、公開後確認まで行う（再確認不要）。個別の「公開しない」指示があれば優先。
- Workers Freeを維持。有料化・R2有効化をしない。シークレットは環境から利用し、コード・ログ・チャットへ書かない。
- 今回の統合には、以前ユーザーが依頼し公開済みの学校用OAuthクライアントID／`kaga.ed.jp`設定も含む。公開用IDは秘密鍵ではない。今回の引き継ぎでvars／migrationsを新たに編集しない。
- フィルタは少ない対象を均等な格子へ配置し、発表の上下左右の2次元移動を維持する。
- 担当のみ表示は通常UI上の一時制限。既に端末に届くデータの厳密な秘匿はユーザー要件ではない。集合中だけ担当外ページを見せ、終了で元へ戻す。
- 安定した行・列ID、Node／Cloudflare双方の権限、既存ZIP互換性、復元先は新規作品、共有復元は既定無効を維持する。
- UIはユーザーの具体的な要望を推定頻度や第三者提案より優先。比較は2〜4枚、5枚以上は理由付きで無効。編集・集合・発表・直接保存の操作数を増やさない。
- 本番データで破壊的な試験をしない。独立したローカルRoom／Directoryと試験認証を用いる。
