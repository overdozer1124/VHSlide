# 0.43.3：ログイン直後の作品復元エラー

2026-10-26（日本時間）。利用者から、ログイン・画面更新の直後に「対応するVHSlideファイルではありません」と表示され、ホストとして作品を開けないとの報告。

## 調査と再現

画面にはアカウントと作品一覧が表示されていた。認証の失敗と断定せず、自動で作品を開く `CloudWorkspace.initialize()` → `openLocation()` → `open()` を調査した。

旧処理は、サーバーから取得したY.Docへ端末のキャッシュを直接適用した後、全体を `parseDeck()` で検証していた。端末の未送信データを合流すると作品形式の条件を満たさなくなる場合、正常なサーバーの内容も開けなくなる。また、Yjsの適用途中で例外になった場合も、直接変更したDocが残っていた。

架空のホスト・400枚の作品・形式不正な未送信キャッシュを使い、同種の開けない状態を再現した。実際の利用者の端末データや公開ルームは取得しておらず、今回の実発生がこの原因と完全に一致するとまでは断定していない。

## 修正

- `src/cloudDocument.ts`：サーバーの作品を先に検証。端末キャッシュは独立した候補Docへ合流し、検証に失敗した候補は破棄する。正常なサーバーDocへ不正な変更を混ぜない。
- `src/cloudCache.ts`：読み込めなかった一時保存をIndexedDBの別キーへ退避した後、作業用キャッシュをサーバーの内容へ切り替える。退避と切り替えは同じreadwrite transaction。途中で別タブがキャッシュを変更した場合も、検査済みのコピーとその時点のコピーを残す。
- 退避に失敗した場合はトランザクションを中止し、元のキャッシュを保持。クラウド保存済み内容を読み取り専用で表示し、再試行できるようにする。保護できていない一時保存を、通常の「開き直す」操作で無条件に上書きしない。
- 再試行中にメモリへ保持していた旧コピーも引き継ぐ。内容が同じバイト列と同じ通信世代のコピーは重複させない。
- `src/CacheRecoveryNotice.tsx`：何を表示しているかを示し、退避データをダウンロードできるようにした。案内を閉じてもデータは削除せず、クラウドの作品一覧からダウンロードできる。
- 復旧用ファイルは `vhslide-local-recovery` 形式のJSON。元のYjsバイト列をBase64で保持する。通常の作品JSONや完全バックアップZIPではなく、現時点では通常のファイル読み込みから復元する機能はない。認証トークンやCookieを加えて出力する処理はないが、作品内容を含むためUIでも保管上の説明を表示する。
- サーバーのデータ自体を検証できない場合は、それを示すエラーへ分ける。端末キャッシュで検証を迂回せず、両方の保存内容を変更しない。
- 正常な未送信データの合流、旧通信世代の配置変更の読み取り専用復旧、共有権限、0.43.2の再接続機能は維持。

## 検証

`src/cloudDocument.test.ts` と `tests/cloud/cache-recovery.spec.ts` を追加。

1. 400枚の作品に不正なキャッシュが残っていても、自動でホストの作品を開ける。サーバーの作品を変更せず、元のキャッシュを退避・ファイル出力できる。復帰後の編集も保存される。
2. Yjsとして壊れたバイト列でも、サーバーの作品へ混ぜない。
3. 退避時の容量不足をテスト限定で注入。元キャッシュが変わらず、編集を停止する。保護の再試行が成功すれば編集へ復帰する。
4. 別タブによる途中の書き換えをテスト限定で発生させ、検査時と直後の両方のコピーを退避する。
5. サーバー応答自体が不正な場合は、認証済み状態を保ちつつ別のエラーとして表示し、キャッシュを上書きしない。

単体試験は128成功、Node APIは16成功。Nodeブラウザの関連試験は36成功。Cloudflareでも同じブラウザ試験を実行し、最終結果・配信照合は `docs/audit-evidence/cache-recovery-0.43.3/` に保存する。

Cloudflareブラウザもデスクトップ・タッチ構成で36件すべて成功。0.43.3を公開し、トップページを含む6ファイルのSHA-256が試験済みビルドと一致すること、`/healthz` が正常応答することを確認した。Cloudflare Version IDは `034ec7a9-d54c-45ae-bb5f-f085becdcfd2`。

Cloudflareの型検査・dry-runも実施。WorkerバンドルのSHA-256は0.43.2でAPI・バックアップ障害試験に合格したバンドルと同一。今回はサーバーAPIの新しい障害試験を追加・再実行したという意味ではない。

公開の共有ルームを読んだり、作品を編集・削除したりする試験は行っていない。Google本番アカウントでの再ログイン、実Chromebook・Windows・iPad端末での確認は未実施。

## 残る制約

- 退避不能時は、データ保護を優先してスライドを読み取り専用にする。容量やIndexedDBの問題が継続する場合、ダウンロードしただけで自動的に編集可能へ切り替える処理にはしていない。
- 複数タブの将来のすべての書き込みを排他制御する機能ではない。今回保証するのは、検査したコピーと退避トランザクション時点のコピーの保護。
- 正常な未送信データを含む候補の検証には一時的に別のDocを用いる。大容量・実機での追加メモリ測定は未実施。
- サーバーに保存されたデータ自体の異常を、自動で情報を削って修復することはしない。
