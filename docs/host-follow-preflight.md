# ホスト追従モード：実装前照合

2026-10-29。対象はユーザー提示の「追従モード実装仕様 v1.0」。現行アプリの基準は0.57.0。これは実装前の調査・設計メモであり、追従機能の実装・動作確認済み報告ではない。

## 結論と停止理由

仕様第7節の「一時表示された制限外ページの内容をローカル保存等へ恒常的に残さない」は、現行の全体配信・全体キャッシュと両立しない。仕様第12節の「既存仕様と衝突する場合は実装を止めて報告」に従い、Step 1のコード変更を含む実装を開始せず、方針の確認を求めた。ソースコード・本番データ・公開環境には今回変更を加えていない。

## 確認中の判断

1. 第7節を維持して、制限外の配信・キャッシュ・復旧方式も変更する設計へ進むか。
2. 既存の全体配信・保存を維持し、第7節を「追従用の追加コピーや保存をしない」に限定するか。

後者は現行の共同編集との互換性を保ちやすいが、元の第7節の厳密な非保持を満たすものではない。前者には、本仕様の「既存仕様を変更しない」との整合を明示的に取り直す必要がある。既存キャッシュを無断で削除すると未送信編集を失い得るため、解決手段として実施しない。

## 方針決定後の段階案（すべて未実装）

1. **状態・権限**：認証済みWebSocketの制御メッセージとして扱い、作品内容のYjs／JSONとは分離。ホストのアカウント権限と開始元接続を検証。セッション世代を持ち、以前の接続・終了通知で新しい追従を終わらせない。対象は行列番号だけでなく安定したページID・シートIDで識別し、行列番号は表示に使用。
2. **表示同期**：ページIDとマップ／ページの状態を同期。ピクセル座標は同期しない。全体マップを全ページ表示するのか、担当範囲＋ホストの注目セルにするのかを確認する。FR-2は前者、未決事項には後者も挙がっている。
3. **ロック・表示**：ゲストの通常画面全体を操作不可とし、ホスト名と追従状態を常時表示。保存済み発表ルートや作品権限そのものは変更しない。
4. **編集保護**：既存編集ツリーを維持して表示用レイヤーを切り替える案を検討。編集中ページ・オブジェクト・Quillの選択範囲・textareaのカーソル／選択・スクロールを保持。未送信更新を破棄しない。IMEの変換途中をどう保持・復帰させるかは独立して検証する。
5. **一時表示**：確認結果に応じ、永続化される編集データと追従用表示の境界を設計する。厳密非保持なら配信・キャッシュの改修と旧キャッシュの安全な取り扱いが先行する。
6. **異常系**：新規参加・再接続時にサーバーの現行追従状態を取得。開始元ホスト接続終了で自動解除。通信断が直ちにclose通知になると仮定せず、期限／接続監視を設計する。CloudflareのHibernation・既存alarm・無料枠との両立を確認する。

各段階でNode・Cloudflareの実実行系の認可／接続試験とブラウザ複数アカウント試験を分ける。実Chromebook・IMEの実機試験をモック試験で代替したことにはしない。

## 追加の未決事項

- 同期遅延：既存のWebSocket試験の成功は、ページ追従の遅延実測ではない。今回は測定していない。制御通信を作品編集の送信待ちに混ぜず、独立試験で分位値を測った後に数値目標を確定する。
- 割り込みメッセージ：提示された文言を候補とし、表示タイミングとともに最終確認する。
- マップの表示範囲：FR-2と第7節の一時表示範囲を同時に満たす定義を決める。
- ホストの複数端末：同じホストアカウントのどの接続を画面同期の基準にするか。開始した接続を基準とし、その接続が切れれば終了する案を上記に記載したが、実装・確定はしていない。
