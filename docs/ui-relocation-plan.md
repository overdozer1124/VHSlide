# VHSlide UI 棚卸し・再配置案

- 対象: VHSlide（現行 v0.61.0）
- 版: v2.0（2026-10-29、Codex レビューを反映した改訂版）
- 状態区分: 本書は「提案」である。頻度の分類は推定を含み、最終判断は開発者が行うこと。ゲスト側画面の棚卸しは未実施。

## 改訂履歴

- v2.0: Codex レビュー（総評：条件付き賛成）を反映。
  - 分割ボタン化と容量説明は現行で対応済みだったため、Step 1 は「作り直し」から「現状確認」に変更した
  - 一括操作は選択ベースではなくシート全体の操作だったため、「選択中のみ表示」案を撤回し、代替案に差し替えた
  - 発表はゲストも使える機能だったため、利用者分類を訂正した（ゲストから隠さない）
  - 縦の連動はページ設定ではなく保存されるナビゲーション設定だったため、扱いを訂正した
  - 棚卸し対象の漏れ（付箋、スピーカーノート、左右パネル折りたたみ、ゲストのページ追加方法）を補った
  - レイアウト図から「ファイルに保存」が落ちていた不整合を修正した
  - 受入条件の定義とステップ順序をレビュー推奨に合わせて見直した

## 1. 目的と原則

後から追加された機能がツールバーに差し込まれ、分類とすっきり感を欠いている状態を、**機能を変えずに配置と見せ方だけ**で整理する。

原則:

1. **同じ機能への入口は1つ**にする。ただし例外として、復旧・再試行のための入口（例： 発表中の「発表者用ノートを開く」）は役割が違うため重複として消さない
2. 分類軸は「機能の種類」ではなく**使う場面**で切る： 作る／そろえる（授業を回す）／見せる／しまう・出す
3. **常時表示は少なく**、文脈でしか意味を持たない操作は必要なときにだけ出す
4. 低頻度のものは「その他（…）」へ寄せる
5. 維持する現行の良さ： 保存状態の常時表示、文字ラベル（アイコンのみにしない）、動詞で書かれたボタン名、保存エラーや再接続の案内

受入条件の定義（レビュー反映）: **すべての動線で操作数を減らすことではない**。常時表示と迷いを減らす。

**操作数の例外（利用者確認済み）**：「新しく／開く／クラウド」の集約で各1クリック増えるのは許容する例外。主要動線のうち編集・集合・発表・保存の操作数は増やさない。

利用者： 先生（ホスト）／子ども（ゲスト）／両方
判断： Codex レビューの項目別判断を反映。

## 4. 移行ステップ（レビュー推奨順）

一括改修はしない。各ステップは原則として配置と見せ方のみの変更で、機能・権限・保存形式を変えないこと。

1. **Step 1: 現状確認（完了扱い）** — 分割ボタンは既にある。ノート付き発表・保存済みルート・保存方式を落とさないことを確認する
2. **Step 2: 低頻度の退避** — 更新履歴・使い方など、状態管理への影響が小さい入口から「その他」へ移す
3. **Step 5（前倒し）: ヘッダー整理** — 集合・発表・作品操作の配置を整え、小画面とゲストで確認する
4. **Step 4: 編集ツール整理** — パレットの開閉と「縦の連動」の到達方法を確認しながら進める
5. **Step 3（最後）: 一括操作と比較** — 一括操作の対象範囲（シート全体）の扱いを確定してから着手する

各ステップ後に確認すること:

- 編集・集合・発表・保存の操作数が増えていないこと。「新しく／開く／クラウド」の集約のみ各1クリック増を許容（第1節の受入条件）
- 既存テストは、削除ではなくメニュー移動に合わせて経路を更新し、機能の受入条件は残すこと
- 小画面のヘッダー高さ（現行テストの上限 104px 以内）を維持すること
- ボタンの文言は変えない。変える場合は更新履歴に明記する

## 5. 実装上の注意（レビューで指摘された落とし穴）

- **パレットとメニューの競合**: 図形パレットは `createPortal` で別 DOM に表示され、共通メニューはフォーカスが外れると閉じる。パレットをメニュー内に丸ごと入れると、操作した瞬間に親メニューが閉じて内容が消える。「もっと見る」はパレット自体の内包ではなく、パレットを開く入口として使うこと
- **入力欄をメニューに入れない**: 共通メニュー（ActionMenu）はボタン項目用で、矢印キーをメニュー移動に使う。倍率の入力欄やネイティブ選択欄はそのまま適用できないため、表示パネル等に分けること
- **ポップアップのタイミング**: スピーカーノート用の別窓はクリック処理内で同期的に開いている。メニュー再編で「閉じた後の effect で起動」に変えると、ブラウザのポップアップ拒否を招く
- **入口を1つにする原則の例外**: 復旧・再試行のための入口（発表中のノート再表示など）は、重複として削除しない

## 6. ゲスト側で維持すべき挙動（レビューより）

- 集合・表示制限・ページ追加方法の変更はホスト限定のまま
- ゲストの発表機能は残す
- 閲覧のみでも付箋を許可されたゲストがいる前提を壊さない
- 担当表示中のフィルタ制限、編集可能範囲、集合終了後の元の状態への復帰を維持する
- 「集合を終了」は小画面でもすぐ操作できる位置に残す

## 7. 注意点・未決事項

- 頻度分類は推定である。実際の授業での使用頻度で棚卸し表を修正してから実装に移ること
- 既存ユーザーの「ボタンの場所の慣れ」があるため、一度に全部を変えない
- ゲスト側（子ども側）画面の棚卸しは未実施。再配置後の使いやすさ、実 Chromebook、スクリーンリーダーでの確認も未実施
- 「図形・線」の扱い（近接配置か「もっと見る」か）はどちらかに決める必要がある
- 「使い方」は低頻度だが新規ユーザーの入口でもある。初回表示や空状態からの導線を残すか要検討
