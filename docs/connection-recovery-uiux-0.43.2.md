# 0.43.2：接続復帰とUI/UX改善・第1段階

2026-10-26（日本時間）。0.43.1の操作停止調査に続く修正と、進行中だったUI/UX改善の第1段階。

## 修正した操作停止の経路

0.43.1では一時的な更新エラーも恒久的な編集停止として扱われていた。今回は、両バックエンドが原因を分類し、クライアントが安全に再接続できるよう変更した。

| 原因                                       | 動作                                                                     |
| ------------------------------------------ | ------------------------------------------------------------------------ |
| 429の操作制限                              | 60秒の待機を尊重して再接続。手動操作やオンライン復帰でも待機を短縮しない |
| 明示的なサービス障害・永続化段階の障害     | 待機し、同じ編集データを保持して再接続                                   |
| 初回の同期応答がない                       | 20秒で検出し、再接続                                                     |
| 保存のACKがない・送信例外                  | 20秒の監視、または送信例外の検出から再接続                               |
| 認証期限切れ・不正データ・通信方式の不一致 | 編集停止を維持。無条件に再送しない                                       |
| 権限による拒否                             | 既存のサーバー認可・権限再確認を維持。再試行を編集権限の迂回に使わない   |

- 自動再接続は初回失敗後最大6回。バックオフは1・2・4・8・16・30秒（サーバー待機が長い場合はそちらを優先）。成功した保存応答などで失敗回数をリセットする。
- 連続失敗後は明示的な停止とし、「接続を再試行」「JSONを保存」を表示する。利用者が再試行する場合もサーバーの待機時間は保持する。
- 同じ `Y.Doc` と `UndoManager` を保持。再接続時に取得するサーバーのstate vectorと差分を計算し、未反映の変更を再送する。確定応答だけが消失しても、サーバーが持つ変更を改めて新しい要素として生成しない。
- 以前のソケットのイベントを無視し、接続ごとにstate vectorと監視タイマーを更新。作品から離れたときはタイマーを解除する。
- `open(id, true)` による未反映データの置き換えを、自動復帰の手段として流用していない。
- 作品・画像・共有・バックアップのデータ形式は変更していない。通信世代は5を維持。旧クライアントは新しい復帰処理を持たないため、画面更新が必要。

実装：`src/syncRecovery.ts`、`src/cloud.ts`、`server/app.ts`、`cloudflare/room.ts`。復旧案内は `src/App.tsx`、`src/style.css`。

## UI/UX改善の第1段階

| 指摘                        | 今回の変更                                                                                                                                                                                                     |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R02：担当の準備状態         | 共有設定プレビュー・共有者一覧で、編集可能枚数、未作成範囲、削除済み範囲を表示。フィルタ内でも準備待ち・閲覧のみ・担当なしを分け、他シートに担当があれば移動できる。権限だけを設定してもページを自動作成しない |
| R03：JSON読み込み後の誤案内 | クラウドから開いたJSONは端末の作品であること、元のクラウド作品は作品一覧から開くことを明示。Undoで元のクラウドへ戻れるという誤案内を削除し、作品一覧へのボタンを追加                                           |
| R03：切り替え時の保護       | クラウドの未保存変更・付箋がある場合は切り替えを中止。端末の作品は読み込み前の版保存が完了してから切り替え、Undoを保持。解析失敗・保存失敗・読み込み中の作品変更では現在の作品を置き換えない                   |
| R05：編集設定の切り替え     | 同じページで対象を変えても選んだタブを保持。空白クリックではページ設定、複数選択では配置、新規挿入やページ移動では見た目、セルを選んだ場合はセルの設定を表示。設定グループごとのスクロール位置を保持           |
| R09：複数セルの混在         | 基本書式と見出しの既定値を解決したうえで比較。文字サイズ・揃え・色・太字・斜体が異なる場合は混在と表示。未変更の数値欄をフォーカス・ぼかしただけでは書式を適用しない。色は明示的に適用できる                   |

実装：`src/assignmentReadiness.ts`、`src/AssignmentStatus.tsx`、`src/PreSharePanel.tsx`、`src/SharingManager.tsx`、`src/MapFilterPanel.tsx`、`src/MapView.tsx`、`src/CloudPanel.tsx`、`src/EditorInspector.tsx`、`src/Editor.tsx`、`src/cellFormatting.ts`、`src/TableCellControls.tsx`、`src/SlideTable.tsx`、`src/ObjectLayout.tsx`、`src/App.tsx`。

フィルタ後の偏りの少ない自動格子配置、ピンチによる画面移動、発表の上下左右ナビゲーションは維持。「元の格子／一覧」切り替えや一方向の一時再生は追加していない。

## 広い回帰試験で見つかった点

- 旧キャッシュ復元の詳細な理由が、新しい接続案内への切り替えで見えなくなっていた。既存の復元専用パネルに復元理由を明示した。
- 共同編集では文字揃えのデータが反映されても、入力用QuillルートがCSSで常に左揃えとされていた。ボックス全体と段落の書式を分け、編集・閲覧で揃えが一致するよう修正。全体の揃え変更時に文字装飾を保持すること、段落ごとの左揃えに戻せることも検証した。`src/richText.ts`、`src/RichTextView.tsx`、`src/App.tsx`、`src/style.css`。
- タッチの付箋試験は、幅の狭いキャンバスでは120pxの最小幅に当たっていた。実装上の相対サイズが変わっても期待した15px以上の増加にならないため、プリセット増加の試験ではサイドバーを折りたたみ、最小幅より十分広いキャンバスを確保した。タッチ入力自体は維持。狭い画面でプリセットの見た目が近くなる制約は、小画面設計の残項目とした。

## 保証の範囲と残項目

- 再現できた「一時的な更新エラー後に再接続しない経路」を修正した。ユーザーの実発生がこの原因だったと断定するものではない。全画面が完全に反応しなくなる別原因まで解決したという判定ではない。
- 実 Chromebook / Windows / iPad による操作・メモリ・ネットワーク切り替えは未検証。Chromiumのデスクトップ・タッチ構成による代替試験。
- 未保存データの保持は、現在のメモリと既存の端末キャッシュに基づく。端末自体の異常終了・保存容量不足まで完全に保証するものではない。JSONや完全バックアップの保存も引き続き必要。
- 権限更新による4004の既存の再確認フローは別経路であり、一般の通信断への復帰として流用していない。
- 原因追跡用の個人情報を含まない専用診断履歴、未作成範囲をマップ上で直接確認する導線、小画面の全面再設計は今後の改善対象。
- 第2段階以降のフィルタ・比較・PDF・発表範囲の統一、保存導線全体、表・グラフの見切れ、小画面編集の再設計は本リリースの完了項目に含めない。
