# 0.40.3 重なったオブジェクトの選択を修正

調査・修正日：2026-10-25（日本時間）。本番ルームのデータにはアクセスせず、ローカルの合成作品で検証した。

## 原因と変更

`src/Canvas.tsx`では要素の配列順にオブジェクトを描画していたが、要素自身はスタッキングコンテキストではなかった。そのため、背面の要素に属する`z-index: 2`の枠、`z-index: 3`のサイズ変更部分、表のセル入力欄などが、前面の図形よりも上でヒットテストされる場合があった。クリック位置と背面の選択状態によって発生が変わる。

修正後は、配列の位置を要素自身の`zIndex`に指定する。子要素の重なり順をその要素の内部に閉じ込め、保存されている順序を表示と選択の両方で使用する。最前面・最背面への変更も同じ配列順で反映し、選択しただけで順序を上げる処理は追加していない。ガイドの表示、別レイヤーの付箋、発表・サムネイルの描画は従来の構造を維持する。新しい重なり順フィールドを保存形式に追加したものではない。

さらに、タッチで背面の表を入力した後に前面の図形を選ぶと、選択表示は図形でも、背面のセルにキーボード入力のフォーカスが残るケースを確認した。`Canvas.selectElement`で別のオブジェクトへ確定選択する際に、古い入力先をblurする。タッチのスワイプ開始時にはblurせず、タップ確定後に実行するため、ページ移動途中でキーボードを閉じる変更にはしていない。

実装変更は`src/Canvas.tsx`、更新履歴とバージョン。データモデル、認証、編集権限、サーバー、ZIP形式に変更はない。

## 検証

`tests/e2e/element-stacking.spec.ts`で、背面に文字または表、前面に図形を配置する。前面の図形が覆う背面の上枠・右下のサイズ変更位置・文字／セルの中央を、スクリーン座標で直接クリック／タップする。`document.elementFromPoint`の最上位オブジェクト、選択表示、残留入力先を確認する。背面の選択・入力状態、並べ替え、再読み込み後も検証した。

修正前は背面の枠が前面の図形より優先することを再現した。試験は全体マップ→編集の遷移アニメーションの完了と、キャンバスのサイズ確定を待ってから座標を計算する。
