## 安全性と互換性

- ZIP version 1を維持。新しいSTORE ZIPのデータディスクリプターも旧0.37.1の読み取りで検証する。旧ZIPも同じ検証関数で読み込む。
- ファイル数、パス、重複、STORE以外、サイズ超過、SHA-256、画像参照とメタデータの妥当性検査は維持。Workerのエラーを成功として扱わない。
- `downloadFullBackup`は画像取得・ZIP生成の完了後、従来どおり`POST /backup/verify`でRoom/Directoryリビジョンを確認してから配布する。変更・ABA・通信失敗・認証失敗・中断では配布しない。無限再試行しない。
- 0.37.1の保証範囲を拡張したとは主張しない。最終検証の読み取り時点より後の編集、別端末の未送信更新は含まない。複数DOを単一トランザクションとして扱わない。
- 復元は新規の非公開ステージング作品へ行い、確定後だけ公開範囲を適用。元作品を上書きしない。共有権限の復元は既定OFF。
- フィンガープリントは従来と同じ「正規化スナップショット＋ソース順に整列した画像SHA-256」から生成。既存ジョブとの照合、画像の冪等キー、確定済み作品の再検出、再読み込み後の再開、取り消し競合の扱いは維持。
- 読み込み時の画像はArrayBufferを転送し、Workerとメインで二重保持しない。プレビューのため画像自体はメイン側で保持する。各アップロードのハッシュもサーバーで再検証される。

## 測定方法

実Chromebookは利用できないため、Linux上のheadless Chromium 154（1366×768、CPU倍率1）による代替試験。低性能端末の再現・授業中の利用保証ではない。

同じマシン、同じローカルHTTP画像取得、同じ画像バイト・画像数・サイズ・作品構造で、凍結した0.37.1と0.37.2をそれぞれ新しいブラウザーで測定。双方ともViteで本番形式にバンドルし、開発サーバーのモジュール変換時間を測定対象から外す。性能測定中に他のテストスイートを並行実行しない。生成日時とスライドUUIDは各試行で生成するため、その文字列自体は異なるが長さとデータ構造は同じ。

画像データ量は5・20・50・100・280 MB（10進）。1点最大5MBの合成バイナリであり、写真デコード・描画・サーバーへの復元時間は測定しない。ZIPはSTOREのため約同サイズ。新形式の管理情報の差は最大約1KB。ネットワーク・スナップショットAPI・最終リビジョンAPIの時間は表に含まない。

- **完了**：生成が完了し、読み込み後の画像数が一致したか。
- **応答性**：16msタイマーの最大実行間隔と、そのタイマーで実行するDOMボタンのクリックハンドラーを記録。表の値はUI遅延の代理指標であり、厳密な入力遅延や停止時間ではない。通常の16msも含む。実機の指操作は未測定。
- **メモリ**：ブラウザープロセスと子プロセス（Workerを含む）の`/proc/*/status`のVmRSSを約50ms間隔で合計。共有ページをプロセスごとに数えるため、専有物理メモリやJSヒープ単独の値ではない。瞬間的なピークは取り逃す可能性がある。Blobの保存先・GCのタイミングにも依存する。
- 各条件1回。中央値・ばらつき・性能保証値ではない。改善前と後で同じ測定方法を適用する。

## 未解決事項・実機で残る試験

1. 読み込みではWorker内にZIP全体と展開画像が一時的に共存する。完全なストリーミング読み込みではない。280MBは依然大きなメモリを必要とする。Worker化はOOM防止の保証ではない。
2. Blobストレージのディスク退避、実ディスクの満杯、OSによるタブ破棄、実メモリ不足時のブラウザークラッシュは未検証。413の保存容量不足試験と、端末のメモリ不足は別問題。通常の例外は案内するが、プロセス自体が終了した場合のメッセージ表示は保証できない。
3. Chromebook（実際の授業端末）で典型作品の5・20MBから確認し、50MB以上・上限付近は別のストレス試験として扱う。処理時間、実タップへの応答、画面描画、タブ復帰、キャンセル後の再選択を測る。iPad・Windowsも実機未検証。
4. 100・280MBの値はアーカイブ処理だけの値。Cloudflareの作成者50MB枠ではそのまま復元できない。容量制限を緩めて成功したかのようには扱わない。大容量のクラウド復元完了は未確認。
5. 単一測定なので、メモリ圧迫条件、繰り返し実行時のGC、他のタブ・共同編集を同時に動かした場合の測定を追加したい。
6. 0.37.1からの継続課題（履歴復元、画像の容量回収、同時構造変更の意味的競合など）は今回の修正対象外。

ローカル代替環境ではBR-4の応答性改善を確認。実Chromebookと上限付近の滑らかな操作性は未検証・改善余地があるため、端末全般の公開品質としては条件付きとする。本番へのデプロイは行っていない。
