# 段階① フェーズ2（製品実装）実施計画 v0.1

作成: Muse（2026-11-05、ドラフト／Codex レビュー用）。根拠: 実装設計書 v2.10 第9節（段階①のタスクと受け入れ条件）、検証計画 v0.4 のフェーズ2、フェーズ1最終報告書（確定版）。

## 1. 確定事項（前提）

- **初代登録方式は A＋C の組み合わせで確定**（開発者、2026-11-05）。一時経路は案A（使い捨てシークレット＋一時経路、登録後に無効化）、運営・復旧の認可は案C の独立認可として設計・実装する。
- 段階①は**検証環境でのみ有効**とし、学校利用の本番有効化は段階②と同時に行う（決定済み）。
- フェーズ1最終報告書の条件を引き継ぐ: 独立認可の設計と実証、旧セッション拒否の実証は、本計画の受入条件に含める（第4節）。

## 2. 実施範囲と順序

検証計画フェーズ2の順序に従います。

1. **移行（C4・C5）**: organizations / preregistrations / organization_members / school_admin_applications / users.is_super_admin の追加とスキーマ移行（列名指定 INSERT への変更を含む）。移行の再実行でデータ・権限が変わらないことを確認する。
2. **認可基盤（C1〜C3）**: 資格照会（サーバーが操作資格を返す仕組み）、既存セッションへの資格変更の反映、Node／Cloudflare で同一の資格判定。
3. **登録制フロー（B群）**: 学校管理者による事前登録とログイン時の結びつけ、学校管理者の申請・任命フロー。事前登録の状態遷移（取消・重複・二重消費・複数校）は実装設計書 第5節どおり。
4. **初代登録の受け入れ（A群）**: A＋C 組み合わせによる初代スーパー管理者の登録と復旧手順の製品実装。運営・復旧の独立認可（認可・無効化・ローテーション・回復の各経路）をここで設計・実装する。
5. **回帰（D群）**: 移行後も既存のログイン・一般作品の作成・共有・復元が従来どおり動くこと（D1）、学校所属のないアカウントへの非干渉（D2）。

## 3. 実装時に確定する事項

- 監査ログを必須にするか任意のままにするか（実装設計書 第10節）。
- 本番で生の sub を記録するか導出済み ID とするか（フェーズ1最終報告書 第9節の確認事項）。フェーズ1試作の記録方法（SHA-256(sub)）はこの判断を先取りしない。
- 表示名の代替方法の採用可否とフォールバックは段階③が主対象だが、資格照会の応答に内部管理フラグや氏名・メールを混入させない境界は段階①で確定する。

## 4. 受入条件

実装設計書 第9節の段階①の受け入れ一覧（学校管理者だけでは作品権限が増えない／教師資格のない学校管理者でも同様／未許可の任命ができない／一般用・学校用のどちらのログインでも同じ登録資格に結びつく／事前登録の取消・重複・別校操作の拒否／二重消費・取消後の結びつけ・所属解除後の自動復活が起きない／既存セッションへの資格変更の反映／移行の再実行で不変／内部管理フラグの混入なし／初代登録の競合・再実行の拒否／既存機能の維持／両サーバーで同じ資格判定／初代登録の並行・失敗後の再試行・環境の取り違え・誤登録からの復旧が手順どおり安全／事前登録の同時消費・取消との競合・複数校が状態遷移どおり）に加えて:

- **独立認可の実証**: 運営・復旧の認可が、共有シークレットではなく独立した運営者認可として働くこと（認可・無効化・ローテーション・回復の各経路を含む）。
- **旧セッション拒否の実証**: 復旧後に、旧アカウントの保持済みセッションから管理操作が拒否されること（フェーズ1で未実施だった項目）。
- 検証は検証環境で行い、本番には段階①の変更を有効化しない。

## 5. 進め方と役割

- 実装は製品リポジトリで行う。分担は現行の枠組みに従う（Codex が実装、本チャットは設計・調整。Codex の使用制限時は「VHSlide実装」チャットで Muse が直接実装する）。
- Muse の Cloudflare トークンはフェーズ1終了時に失効済みです。Muse が検証用 Worker を操作する工程が必要になった場合は、その時点で開発者が新しいトークンを発行します（工程の前提として記録）。
- 本計画はレビューで確定してから着手します。範囲の拡大や設計変更が必要になった場合は、実施前に開発者の判断を仰ぎます。

## 6. 完了条件

- 第4節の受入条件をすべて満たし、検証記録が残ること。
- 段階②の着手判断は、完了後に開発者が行う（本計画の完了は本番有効化を含まない）。
