# 閲覧のみの操作表示 — v0.61.8

2026-10-30（日本時間）。[ゲスト画面の棚卸し](ui-relocation-guest-review.md)で残った、閲覧のみでもページの変更操作が利用可能に見える点への対応。

## 変更と範囲

- `src/App.tsx`：クラウドの`access.mode === "none"`をマップと共有サムネイルメニューへ渡す。
- `src/MapView.tsx`：閲覧のみのとき、ページの追加、単体削除、ページ・行・列の移動、ページメニューの小ボタン、空きマスへの追加を無効化。ネイティブドラッグとタッチ移動の起動元もなくし、閲覧のみへ変更されたら移動状態と削除確認を解除する。
- マップに「閲覧のみです。ページの追加・移動・削除はできません。」を表示。ページを開く操作のアクセシブル名は「編集」から「表示」へ変更し、更新履歴にも明記。
- 選択中のDelete／Backspaceは、選択ページすべての編集を許可されている場合だけ削除確認へ進む。比較・選択・フィルタの操作は維持。
- `src/ThumbnailMenu.tsx`：マップの右クリックや編集画面のサムネイルの複製・削除メニューも、閲覧のみでは無効化し理由を表示。すべて無効でもメニュー自体へフォーカスし、Escで元のサムネイルへ戻せる。行の複製数入力も無効化。
- `src/style.css`：理由の表示と無効状態の見せ方。移動操作を無効にしても、行番号は情報として読める濃さを維持する。
- 更新履歴とpackage／lockのバージョンは0.61.8。

対象は**閲覧のみモード**。編集を許可されたゲスト（all／scoped）とローカル作品は、マップ全体を閲覧専用扱いにしない。担当行でのページ追加、ホストの追加方法の設定、編集可能範囲、行列ID、保存形式、同期プロトコル、Node／Cloudflareの認可コードは変更していない。

この表示制御は認可の代替ではない。scopedゲストの移動先や構造変更等の可否は、従来どおり既存のクライアント・サーバー判定で決まる。すべての操作を事前シミュレーションしてマップ全体のボタンを再計算する変更は行っていない。

## 検証方法

`tests/cloud/guest-inventory.spec.ts`を拡張。テスト用の別アカウントと独立したRoom／Directoryを使用し、本番ルームは使わない。

- 担当あり・閲覧と付箋のみ・閲覧のみの3種、PC／タッチ設定、1366／1024／810px幅で主操作・無効状態・ドラッグ属性を検査。
- 閲覧のみの右クリックメニューの無効状態・理由・フォーカス・Esc復帰、Ctrlによる追加選択、2ページの比較、削除キーで確認画面が出ないことを確認。
- タッチ設定ではCDPで350msの長押しと移動を送り、タッチ移動プレビューと移動状態が起動しないことを確認。実Chromebookでの試験とは区別する。
- 無効な削除ボタンへの強制クリックでもページ数・サーバーの作品を変えず、削除成功通知も出さないことを確認。0.61.7の削除失敗通知テストは、通常のクリック自体が不能となるため、無効状態と作品不変・成功と誤認しない検査へ更新した。ホストの実際の削除・Undoの検査は残した。DOMや通信を改ざんした攻撃への認可検証を、このUI試験で済ませたとは扱わない。
- 新しい権限切替の試験では、編集可で移動開始→閲覧のみに変更して解除→編集可へ戻して操作再開を確認。権限変更の前後で作品データが不変であることも検査。
- メニューや選択・倍率の既存ブラウザ試験も実行し、既存の受入条件を削除しない。

## 初回の試験調整

初回の追加試験は、Ctrlなしでの追加選択、権限変更の前後で固定メニューが開いたままであること、比較表示画面に選択用チェックボックスがあることを仮定して失敗した。既存のCtrl追加選択、配置変更時のメニュー閉鎖、選択済みページの比較表示に合わせて試験を修正。アプリの機能仕様をこれらの仮定に合わせて変更していない。初回ログを証拠に保存。
