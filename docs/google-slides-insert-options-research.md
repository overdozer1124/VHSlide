# Googleスライドの挿入機能とMatlideaの実装候補

調査日：2026-10-25。対象：VHSlide 0.40.3のコード、Google公式Slides API Discovery仕様（revision `20260930`）。

**この文書は一次選定案。Googleスライドの現行UI・挿入メニュー・プラン別の提供条件は公式ヘルプでの確認待ちであり、最新版の画面を独立検証した報告ではない。**

公式ヘルプへのHTTPS接続はクラウド環境の通信制限によりCONNECT 403となった。`support.google.com`と`developers.google.com`を追加する環境設定案は保存済みだが、適用には利用者の確認・保存とPublishが必要。制限を別のプロキシや本番Worker経由で回避する調査は行っていない。

一方、接続可能なGoogle公式GitHubリポジトリからAPI仕様を取得し、コミットを固定して確認した。APIに型・プロパティがあること、APIで作成・更新できること、GoogleスライドのUIで同じ操作ができることは区別する。APIで定義されないオブジェクトがUIにもない、とは判定しない。

アプリのコード変更・デプロイはしていない。変更は本調査資料と接続先追加の設定案のみ。

## 1. 推奨する選定方針

まず「文字・画像・図形・線・表」と共通の編集操作を充実させる。これらはローカル描画を中心に実装でき、動画・音声の大量保存や追加のGoogle連携を必須にしない。スライド自体の固定グリッドは維持し、その中の表現力を増やす。

オブジェクトの種類と、編集操作の充実は別の課題として管理する。例えば、三角形が増えても図形内に文字を書けず、複数選択や整列ができなければ、Googleスライドのような制作体験には届かない。

### C：現時点では後回しを推奨

- **動画・音声の自前保存**：現行の画像専用アップロード、容量管理、削除済みメディアの認可、ZIP内の参照収集を一般メディアへ拡張する必要がある。再生タグを置くだけでは、翌日以降の復元や個人情報保護を維持できない。
- **YouTube等の外部動画**：保存容量は抑えやすいが、外部通信・広告・学校の接続制限・再生制約を確認してから選ぶ。アプリ内の広告を入れない方針との関係も整理する。
- **Drive／Sheetsとの深い連携**：追加のGoogle権限、ファイルの共有、組織側の許可が関係する。まず作品内に完結する編集機能を独立して実装できる。
- **AI画像・図解生成**：料金・提供条件・入力内容の外部送信が関係する。無料提供の方針に合わせ、利用者が明示的に選べる独立機能として検討する。
- **Web画像検索・外部素材検索**：API利用条件、素材ライセンス、外部URLの永続性が関係する。まずライセンスを確認した少数の内蔵素材・プリセットを検討する。
- **スピーカースポットライト等のカメラ・録画機能**：現在の用途での需要と、学校端末の対応・提供条件を確認してから判断する。

## 5. UIを増やしすぎない構成

挿入の入口は「文字／画像／図形／線／表／その他」程度に整理する。付箋コメントは権限や投稿者管理が異なるため、通常の図形と混ぜない。図形はカテゴリ別のアイコンパレットにし、すべてを長いセレクトボックスへ詰めない。

右側の設定は選択対象に応じて「文字」「塗り・線」「配置」「画像」等を切り替える。高度な設定は展開式にし、Chromebookで常時ヘッダーを増やさない。追加パネルは0.40.1のクリッピング修正を踏まえ、表示領域と物理クリック・タップを共通して検証する。

操作原則は「内容上の指スワイプはページ移動」「枠はオブジェクト移動」「文字・セルは直接入力」「右下はサイズ変更」を維持する。ペン・線の端点・トリミングなどが加わるときも、どのモードかを明示する。オブジェクトの選択や編集中の状態によって、保存している前後関係を勝手に変えない。

## 6. 実装前に仕様へ入れる条件

1. 旧JSONを読み込めること。新しい情報の省略時の既定値を決め、旧版アプリで開ける範囲も明記する。
2. 新しいスタイルや要素をNode／Cloudflare双方で検証し、許可されたプロパティだけを受け付ける。任意のHTML・SVG文字列を無検証に描画しない。
3. ローカル・共同編集・本人Undo・JSON・ZIP・保存した版・発表・PDFで表現を保持する。全機能をGoogle APIに依存させる必要はない。
4. 複製・グループ・コネクタでは、IDと参照関係をまとめて再割当する。別のスライドや担当範囲を参照・変更する抜け道を作らない。
5. メディアを追加する場合、容量・バックアップ・未参照データの取得制限も同時に対応する。
6. 1000スライド・Chromebookを前提に、画面内だけの描画、サムネイルの軽量表示、入力中の応答性を検証する。
