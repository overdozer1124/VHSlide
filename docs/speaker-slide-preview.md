# スピーカーノートのスライドプレビュー（v0.61.0）

スピーカーノート画面に「投影中のスライド」を追加する。広い画面では左にスライド・右に発表メモ、小さい画面では上下に並べる。メニューからの一括開始・発表中の手動起動のどちらにも適用する。

## 実装

- `src/PresentationView.tsx`: 現在ページのプレビューを既存の同一origin BroadcastChannelへ渡す。不要な再送を避けるため、ページ・メモ・移動可否が変わった場合に状態を更新する。
- `src/speakerChannel.ts`: `speakerPreview`でスライド本体からノート項目を除く。受信側は`readSpeakerState`から既存の作品パーサーを使い、画像URLなどを検証した表示用コピーを得る。ページ座標はプレビュー内で使わず、行列番号は既存の表示用情報で保持する。
- `src/SpeakerWindow.tsx`: `SpeakerSlidePreview`が投影画面と同じ読み取り専用Canvasを使う。文字・画像・表・図形・グラフ等の見え方を共通にする。実際の表示要素が生成された時点でサイズ計算／ResizeObserverを開始し、画面サイズに応じて比率を保って収める。本文・ノートの編集やリンク移動はプレビューから行わない。
- `src/useSpeakerWindow.ts`: 状態のリビジョンを使い、定期通信は軽量なalive通知にする。変更のない画像入りスライドを2秒ごとに複製しない。別窓の再読み込み・再表示時や受信した版が異なる時は、現在状態を再送する。
- 古い発表画面からプレビューなしの状態が届いても、従来のノートと操作は表示し、発表画面の更新を案内する。
- `src/style.css`: 広い画面の2列、小画面の1列配置。発表者用ウィンドウの初期幅も広げる。

投影用スライドへノートは表示しない。共有・サーバー権限・発表範囲・上下左右移動・保存済みルート・作品／バックアップ形式は変更しない。通信は従来のランダムな同一originチャンネルに限定し、サーバーへプレビューを保存しない。

## 検証

- 単体173件・Node API18件成功。プレビューからのノート除外、スライド内容の保持、不正な要素／画像URLの拒否、旧状態との互換性を確認。
- PC／タッチのブラウザ16件成功。現在スライドの内容・画像の読み込み・表／図形／グラフ、上下左右移動、両ウィンドウからの移動、別窓の再読み込みと再表示、フィルタ範囲の維持、終了、ポップアップ再試行、表示チェック経由の起動を確認。
- 1366×768／700×900で配置とCanvasの実寸を測定し、画面内に収まることを確認。
- 軽量な定期通知が続いても、変更のないスライド本体の送信回数が増えないことを確認。
- ビルド・型検査・Cloudflare dry-run成功。

途中の1件の失敗は、テストがページ切替を待たずArrowLeft→ArrowDownを連続送信し、移動前の表示では下方向が無効だったため。表示の更新を待つよう修正し、全16件を再実行して成功した。Linux Chromiumによる代替検証であり、物理Chromebook・外部モニターでの実機検証ではない。

証拠：`audit-evidence/speaker-preview-0.61.0/`。全E2Eスイートは今回実行しておらず、従来からのタッチ版バックアップ復元UIの未解決事項は別件として残る。
