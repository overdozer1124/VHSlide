# UI再配置後の全体回帰試験と修正 — v0.61.9

2026-10-30（日本時間）。UI再配置後に未実施だった全体のブラウザ回帰試験を実行し、失敗を切り分けた。本番ルームは試験に使用していない。

## 初回の結果

v0.61.8の本番用ビルドを`playwright.preview.config.ts`で固定し、2ワーカーで全380件を実行。310件成功、53件スキップ、17件失敗。以前の「既知8種類」のリストだけで判定せず、現在の失敗ログ・DOM・実際の操作を調べた。

53件は既存の端末別条件等によるスキップで、今回失敗を隠すために追加したものではない。APIをモックしない一部のローカル試験は、存在しないローカルNodeバックエンド（127.0.0.1:3000）へのプロキシエラーを出す。これは公開環境の通信障害という意味ではない。

## アプリで確認し修正した問題

### 表セルのタップがサイズ変更に化ける

- Linux Chromiumのタッチ設定で、表3行3列のセル内の空白をタップしてもフォーカスが2行2列に残る現象が、単独試験で3回とも再現。
- 一時的な入力イベント記録では、`elementFromPoint()`の実際の位置は対象セルの`.table-cell-content`だったが、ブラウザが送ったpointerdownのターゲットは下辺の`resize-handle`だった。近くのネイティブボタンへのタッチ補正によるもの。
- `src/Canvas.tsx`のpointerdown captureで、タッチの送信先が枠ボタンでも物理位置が表セル内部なら、元のイベントをキャンセルして、そのセルの既存pointerdown処理へ座標・pointer ID・修飾キーを引き継ぐ。セル側の既存のフォーカス・範囲選択処理を再利用し、表データやサイズを変更しない。
- 実際に枠を触った場合、マウス、閲覧専用のCanvasはこの分岐の対象外。

### 小さい画像で四隅の操作範囲が重なる

- 20×20の画像をタッチ設定で表示すると、24pxの四隅のボタンが重なり、右下ボタンの中央位置にある実要素が左上ボタンになることをイベント記録で確認。右下へドラッグすると左上の縮小操作となり、最小サイズ20のまま。これは保存待ちを追加しても解決しなかった。
- `src/Canvas.tsx`の要素・グループ枠に寸法の半分をCSS変数で渡し、`src/style.css`で各隅が内側へ入る距離をその半分以内に制限。押せる範囲全体の16px／タッチ24pxは維持し、残りの領域を外側へ配置する。
- 通常サイズでは従来と同じ見た目。小さい場合だけ可視マークも寸法以内に収める。角のマークは実際の角に置いたまま、異なる隅の操作範囲を重ねない。
- `tests/e2e/resize-frame.spec.ts`に、小さい画像の四隅の実ヒット要素・範囲の非重複・右下からの実際の拡大を確認するPC／タッチの2件を追加。

### リンク確認画面にフォーカスがあるとEscが効かない

- `src/App.tsx`の全体キー処理は`role=dialog`内部の入力を対象外にするため、発表対象外のリンク確認ボタンへフォーカスが移った後はEscで閉じられなかった。フォーカスのタイミングによってPCでは通る場合があった。
- `src/PresentationView.tsx`の確認画面自身でEscを処理し、既存のキャンセル処理で発表へ戻る。リンクを開く前の明示確認、発表範囲の固定は維持。
- `tests/e2e/page-scope.spec.ts`は確認ボタンへ明示的にフォーカスしてからEscを送り、確認画面が消えたことも検査する。

## テストの修正（アプリの仕様変更とは区別）

- `content-fit.spec.ts`：グラフの期待値を実際の入力形式であるJSON境界に合わせ、-0→0を区別しない。長い名前・値・項目数は引き続き完全比較する。PDFの変更なし検査は、空セルが補完された読み込み後のデータを基準にする。
- `editor-interactions.spec.ts`：ページ位置を広すぎる`.canvas-title > span`ではなく、既存の`.canvas-page-position`で検査。
- `row-thumbnail-drops.spec.ts`：Undo後の永続保存をpollで待ち、元の全スライドとの完全一致は維持。単独の元試験では安定して通る場合があり、アプリのUndo処理自体は変更していない。
- `page-scope.spec.ts`／`structure-editing.spec.ts`：廃止されたリンク専用ボタンではなく、発表中はオブジェクトのクリック、編集中はCtrlクリックを使う。シート外リンクの明示確認と、発表終了後に元の編集画面へ戻る現行仕様に合わせた。
- `tables.spec.ts`：表の見切れの表示チェックを明示的に確認してから発表する。同じ内容に対する確認済みの判断はPDFでも再利用されるため、二度目の同一警告が必ず出るという仮定は置かない。表の内容、寸法、JSON、Undo、発表、PDF出力の検査は残す。
- 試験の削除・新たなskip・リトライによる失敗の隠蔽は行っていない。一時的な診断用specは診断後に削除し、診断ログを証拠に保存。

## 検証の範囲と制限

Linux ChromiumのPC／タッチ設定によるローカル試験。実Chromebook、実学校回線、スクリーンリーダー、実Googleログインは未確認。全体E2Eは通常の画面試験であり、全クラウド試験一括実行とは異なる。

権限・行列ID・ZIP形式・同期プロトコル・データベース・認証設定は今回変更していない。

証拠：`docs/audit-evidence/ui-relocation-full-regression/`。初回の全体ログ、失敗時DOM、単独反復、入力座標と実ターゲットの診断ログ、修正後の実行ログを保存する。

## 最終確認と実行順

- `npm test`：アプリ173件、Nodeサーバー18件、成功。ビルドとCloudflare型チェック・dry-runも成功。既存のバンドルサイズ警告あり。
- アプリ修正後の同一ビルドで、追加2件を含む全382件を実行：327件成功・53件スキップ・2件失敗。失敗はPC／タッチの同じスピーカーノート試験で、閉じるクリック中にウィンドウが閉じ、PlaywrightがTargetClosedを返すものだった。試験が記録していた状態配信回数とkeepaliveの検査は、その前に成功していた。
- 当該試験は、閉じる操作時の例外でも実際に窓が閉じている場合だけ受け入れ、閉鎖の確認・同じノートの別窓再表示・内容の確認を続行するよう調整。PC／タッチ各3回、計6件の反復が成功。アプリの窓を閉じる処理は変更していない。この最後のテスト基盤の変更後は当該試験を再実行し、全382件をもう一度一括では回していない。全体コマンドが一度ですべて成功したとは記載しない。
- Cloudflare相当の関連ブラウザ試験8件が成功。閲覧者の編集禁止と付箋、担当ページの追加・制限、集合中の編集状態保持・担当外ページの一時表示を含む。独立したローカルworkerd／SQLite型Durable Objectsとテスト認証を使用。
- 実際のバグの単独再現は、修正前のタッチ画像・表が各3回失敗。修正後は両者とも各3回成功。小さい画像の4つの隅の独立性、通常サイズの枠操作、リンク確認・キャンセル・戻るは全体試験でも成功した。
- 一時的な診断用specは削除済み。今回、失敗を除外するためにskipやretryを追加していない。
