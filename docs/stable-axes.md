# 行・列の担当と権限（0.36.1）

行・列の表示番号と、その行・列の識別子を分離した。対象は担当・権限の整合性の改善であり、完全バックアップや発表ルートの追加ではない。

## 操作の規則

| 操作                                         | 担当・権限・見出し                                                           |
| -------------------------------------------- | ---------------------------------------------------------------------------- |
| 行・列全体の入れ替え／行の並べ替え           | 内容と一緒に移動する                                                         |
| 行・列全体の挿入                             | 既存の担当は後ろへ移動する。新しい行・列は未割り当て                         |
| 行の複製                                     | 内容を複製する。新しい行への担当権限は引き継がない                           |
| 行の削除                                     | その行の識別子を削除し、後続の担当を維持する。削除した担当は他の行へ移らない |
| 個別ページの移動・入れ替え／一行内だけの挿入 | 行・列の識別子は固定。移動先の範囲権限が適用される                           |
| スライドIDによる個別権限                     | 移動しても同じスライドに適用される                                           |
| シート複製                                   | シートIDが新しくなるため、元のシートの範囲権限は適用されない                 |

範囲権限は行・列・個別指定の**和集合**。他の列権限や「全スライド編集」を持つ人まで、新規行を編集不可にするという意味ではない。

行・列全体の構造操作でシートの識別子対応を変更できるのはホストだけ。クライアントが個別ページを移動する場合も、移動前後両方の対象に編集権限が必要。UIに加えNode／Cloudflare双方のYjs更新認可で検証する。

## データと既存作品

`Deck.version`は1のまま。各`Sheet`に任意の`rowIds`／`columnIds`を追加した。

```json
{
  "id": "main",
  "name": "シート1",
  "rowIds": { "0": "1", "1": "0" },
  "columnIds": {}
}
```

この例は元の1行目と2行目を入れ替えた状態。マップのキーが現在の0始まり表示位置、値が安定ID。省略した位置のIDはその位置の10進文字列とする。新規の行・列には`axis-<UUID>`を割り当てる。暗黙のIDも含む100位置で重複する対応は読み込み時に拒否する。

権限の軸指定は`{ sheetId, index, axisId? }`。`axisId`が判定の基準で、`index`は作成時の位置。旧DBに保存された`axisId`のない指定は`String(index)`という既存IDとして読む。したがって既存の共有アカウント、参加前の割り当て、SQLiteの権限レコードを一括書き換えずに利用できる。画面に表示する現在の行番号はIDから逆引きする。

シートの見出し、担当者の縦書き、フッター、編集エリア上部、権限選択、順次行割り当ては同じ対応を参照する。既に以前の版で入れ替え済みの作品について、当時の担当者の意図を推測して復元することはしない。更新直前の位置・権限を起点とする。

JSONには対応を保存するが、従来どおり権限DB・付箋は含めない。旧版アプリでJSONを再保存すると追加情報が落ちる可能性があるため、編集には0.36.1以降を使用する。

## 共同編集と更新時の保護

- 安定ID対応・見出しと座標は同じYjsトランザクションで変更し、自己Undoの対象にする。通常の遠隔テキスト変更はそのUndoに含めない。
- WebSocketのhelloとupdateに`protocol: 2`を使用する。旧画面の更新はサーバーが保存前に拒否し、JSON保存と再読み込みを案内する。新画面も旧サーバーへの送信を停止する。Node版はフロントとバックエンドをセットで更新する。
- IndexedDBの新キャッシュは`{ protocol: 2, data: Uint8Array }`で保存する。旧キャッシュも読み取れる。旧キャッシュの統合で配置や軸IDが変わる場合、自動送信せず復元内容を読み取り専用で開く。JSONを保存した上で、クラウド画面の作品カードから「開き直す」を選ぶ。明示的な確認まで旧キャッシュを保持する。
- 同じホストが複数端末で構造を同時変更した際の意味的な競合、見出しJSON単位の競合は、この変更だけで解消したとは扱わない。複数ホスト端末での同時並べ替えを支える排他・競合UIは別途設計が必要。

## 検証

`src/axes.test.ts`で旧権限の追随、見出し・担当名、行列の挿入、複製・削除、個別移動の移動前後認可、JSON復元、不正ID、シート分離、遠隔テキストを保つUndo/Redoを検証する。

NodeとCloudflareのバックエンドテストは実際のWebSocketを使い、旧形式の行権限設定からホストが並べ替えた後、本人の元の作品を編集でき、別の作品への更新を拒否し、永続化状態に反映しないことを検証する。旧プロトコルの拒否も対象。

ブラウザのクラウドテストには、旧版の未送信配置キャッシュを復元してもサーバーへ送信されず、明示的に開き直せるケースを追加した。実際のGoogleアカウントや公開ルームのデータを使う試験ではない。
