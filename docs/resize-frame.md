# 選択枠からのサイズ変更（v0.59.0）

## 操作

- 選択枠の上・下は高さ、左・右は幅、四隅は縦横を変更する。従来の右下の丸いハンドルは廃止し、小さい四角の四隅と辺の操作領域に変更した。
- 反対側の辺・角を固定する。最小20、スライドの範囲を維持する。
- 画像などの比率固定設定を維持する。比率固定の辺を動かすと、もう一方の軸は中心を維持して拡大縮小する。Shiftを押して開始した場合も比率を固定する。
- 複数選択した全体の枠でも操作できる。全体のリサイズは既存同様に比率を維持する。
- 選択枠をAltキーとともにドラッグすると移動する。未選択の枠からの移動、表のセル内入力、文字上のスワイプ、線の端点編集は維持する。
- 選択中の辺の操作領域は内容の外側へ寄せ、文字上のスワイプや入力を妨げない。キャンバスの倍率にかかわらず操作領域の画面上の幅を保つ。

## 実装

- `src/objectEditing.ts`: `resizeBoxFromHandle`／`resizeElementFromHandle`。反対側の固定、境界、最小寸法、比率固定。
- `src/structuredEditing.ts`: `resizeSelectionFromHandle`。全体の比率、各要素の最小寸法、線端点を変換する。
- `src/Canvas.tsx`: `ResizeFrame`とpointer captureを既存のドラッグ保存／Undoへ接続。1回のドラッグを1回の変更として保存する。本文や表セルは書き換えない。
- `src/style.css`: 外側の四辺と四隅の操作領域、方向別カーソル、小さい四角の表示。
- `src/Editor.tsx`、`src/EditorInspector.tsx`、`src/ObjectPalette.tsx`、`src/InkControls.tsx`、`src/App.tsx`: 操作案内を更新。
- `src/releaseHistory.ts`、package／lock: v0.59.0。

作品形式・共有権限・同期プロトコル・バックアップ形式は変更しない。従来の右下操作のアクセシブル名は互換性のため残し、新しい辺と角には方向別の名前を付けた。

右下の丸だけでなく、8方向すべての変更とUndoをブラウザで検証した。表・文字の内容保持、画像の比率、全体リサイズの固定点、Alt移動も確認。従来の「選択枠で移動」を期待する試験は、今回の操作変更に合わせAlt移動へ更新した。

実際に発見した競合：新しい辺の操作領域が文字の先頭行を覆うと、文字上からのタッチスワイプが始まらなかった。領域を外側へ移し、選択中の旧移動帯を無効化して解消した。既存のスワイプ回帰で確認した。

## 別件の未解決事項：タッチ版バックアップ復元UI

`tests/cloud/tables.spec.ts`の最後のZIP復元で、「新しい作品に復元する」のクリックが`.backup-preview`等に遮られタイムアウトする。セル共同編集、権限、自分のUndo、ZIP取得までは進むが、この試験を成功扱いにはしていない。

切り分けとして、公開中v0.58.1のHTML／JS／CSS／Workerの静的ファイルだけをGET取得し、別ポート3198の独立したローカルNode環境で配信。旧画面＋ローカルの検証用アカウント／Roomで、互換ZIPを読み込ませ、同じ復元ボタンの遮蔽を再現した。初期の比較準備でのブラウザ種別・欠落Workerファイル等の失敗は再現根拠とせず、必要な静的ファイルを揃えて実際の復元確認まで到達した`baseline-restore.log`を根拠とする。本番の作品・アカウントへアクセスしたり、書き込んだりしていない。

これは今回の変更前にもある問題として記録し、今回のサイズ変更でCloudPanelや復元処理を変更することはしていない。実Chromebookでの検証、バックアップ復元UIの改善、全E2Eスイートの再検証は残る。

証拠：`docs/audit-evidence/resize-frame-0.59.0/`。Linux ChromiumでのPC・タッチ代替検証であり、実端末の検証ではない。
