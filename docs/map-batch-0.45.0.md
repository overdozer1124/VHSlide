# 0.45.0：行・列の一括操作とスライドの複数選択

2026-10-26。既存の2次元配置、安定した軸ID、編集権限、Undo、フィルタからの発表を維持した追加。

## 操作

- マップの「行・列を一括操作」から、行／列、追加／削除、開始番号、数を指定する。追加は指定位置の手前（末尾番号なら末尾）へ、反対側の軸の幅だけ空白ページを作る。例：1行だけの作品に9列を追加し、次に39行を追加すると10列×40行になる。見出しだけの空行を作る機能ではない。
- 実行前にページ増減数を表示。縦横100枠と、別シートを含む作品全体1000ページの上限を検査する。フィルタ中でもこの操作はシート全体に作用することをパネルに明示した。構造の一括変更はホストのみ。
- 「選択」を押すと、通常のページ移動ドラッグから範囲選択へ切り替わる。マウス／タッチで囲む、Ctrl／⌘クリックで追加・解除、Shiftクリックで直前の基点との矩形範囲を選べる。Ctrl／Shiftクリックから選択モードを開始することもできる。タッチではタップで追加・解除する。
- 選択モードのページボタンはSpace／Enterでも切り替えられる。Ctrl／⌘+Aは表示対象をすべて選択、Deleteは削除確認、Escapeは選択を終了。入力欄ではこれらを横取りしない。選択を終了すれば従来の編集クリック・マス目間ドラッグへ戻る。
- 選んだIDをそのままフィルタへ渡せる。4枚なら2×2の格子、ズーム、編集画面への移動、対象内での2次元発表を維持する。
- 個別の複数削除は対象数を確認して実行。選ばれていないページの座標を詰めたり移動したりしない。行・列の削除では、その軸だけ後続位置を詰める。どちらも(0,0)が空く場合は新規の空白ページを残す。既存保存形式が先頭ページを必要とするため。
- 一括操作は1回の変更としてUndo可能。端末作品は既存の削除前バージョン保存が成功してから削除する。保存中に作品が変わった場合や保存できない場合は削除しない。削除を受け付けた時点で選択IDを消さず、失敗後も再試行できるようにした。

## 実装

| ファイル                               | 役割                                                                                                                    |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `src/mapBatch.ts`                      | シート単位の一括挿入・削除と個別ID削除。`remapAxis`により軸ID・見出しを追従。削除した軸の権限を新しい位置に引き継がない |
| `src/MapBatchPanel.tsx`                | 対象・数・影響・上限の確認。即時に元作品を変更しない                                                                    |
| `src/useMapSelection.ts`               | Pointer Events、矩形選択、Ctrl／Shift、タッチ、キャプチャ取消。描画更新はrequestAnimationFrameでまとめる                |
| `src/MapView.tsx`                      | 選択中の強調、確認、フィルタ化、キー操作、ドラッグとの切替                                                              |
| `src/App.tsx`                          | 最新作品に対する一括コミット、全シートの上限、ホスト／ページごとの権限再検査                                            |
| `src/style.css`                        | 一時ツール欄、選択枠、入力欄・先頭バッジとの干渉防止                                                                    |
| `src/releaseHistory.ts`、package／lock | バージョンと利用者向け履歴                                                                                              |

選択は表示対象だけで、認可の代わりにはしない。編集できないページを含む個別削除は一部だけ実行せず全件拒否。実行時にも再確認し、CloudWorkspace.applyと既存のNode／Cloudflareサーバーの認可を通す。先頭を削除して空白ページを新規作成する場合、その位置への追加権限も既存の認可で検査される。ページIDだけに権限がある利用者などではこの操作が拒否される場合があり、ホスト権限へ昇格させて回避する処理はない。

JSONのスキーマ、共同編集の通信世代、バックエンドAPIは変更していない。独立した複数ホスト端末からの同時構造変更に対する排他制御は追加していない。

初回は試験側の部分一致ラベルが複数入力に一致したため、完全一致へ修正。既存のドラッグ後Undo試験では、React反映直後にLocalStorageを1回だけ読むアサーションが失敗したため、同じ全ページの完全一致を待って検証するよう修正した。期待内容を減らしたりUndo回数を増やしたりしたものではない。

## 限界

- 実Chromebook・Windows・iPadの実機検証は未実施。Linux Chromiumとタッチエミュレーションによる代替確認。
- 矩形選択は現在見えている領域を囲む操作。スクロールに追従する自動スクロールは追加していない。離れた場所は通常のスクロールとCtrl／⌘追加選択、番号表示、全件選択を使える。タッチの選択モードでは範囲選択を優先し、通常の1本指スクロールは選択を終了して行う。
- 本バージョンでは任意の非連続行・列そのものの一括構造削除は追加していない。構造削除は開始番号＋連続数、任意ページの削除は複数選択で行う。
- 全ブラウザ試験の網羅的な再実行ではなく、変更に関係する試験を実施した。
