# 編集画面のUI/UX見直し（0.43.1）

2026-10-25。0.43.0までの編集機能を、機能の有無ではなく「入力する・選ぶ・設定を探す・編集へ戻る」の流れで確認した。公開ルーム・本番データは使用せず、ローカルの独立作品を使用。本番デプロイは行わない。

## 判断と今回の改善

| 問題 | 確認した根拠 | 改善 |
| --- | --- | --- |
| 空のセルにも上下矢印が出て、操作ボタンに見える | `SlideTable.tsx/AutoCellText`と`style.css`の`.table-cell-content textarea {overflow:auto}`。アプリ側の矢印ボタンはない。ネイティブスクロールバーの表示 | セルのスクロールバーを非表示にし、文字入力・キャレット移動・内部スクロールは維持。長文でセルや表の外枠が拡張しないことも検証 |
| セルの文字がない余白を押すと表の移動になる | `SlideTable`の`onPointerDown`がtextarea以外をすべて移動として処理 | セル内容の余白から入力欄へフォーカス。外枠と細い罫線からの移動は維持 |
| 設定が縦に積まれ、配置やリンクまで到達しにくい | `Editor.tsx`で種類別書式、リンク、配置を同じ縦列に連続描画 | `EditorInspector.tsx`で「見た目・配置・リンク」の3つに分離。選択対象・複製・削除・タブは上に残し、設定内容だけスクロール |
| 何を編集中かが分かりにくい | 従来は種類を問わず「選んだものを編集」 | 「文字・画像・図形・表・線・グラフ」、複数選択数、表の行列数を明示。対象変更時に見た目へ戻る。複数選択時は一括配置を表示 |
| 表全体とセルの設定、説明が重複 | `TableCellControls`と`TableControls`の長文説明・見出し・設定が同居 | 「セル・表全体」を切り替え。セルクリックでセル書式へ。文字色・背景・大きさ・揃えを短いまとまりへ配置し、操作説明は1か所の「表の操作ヒント」へ |
| 行・列の削除が追加と同じ位置に常に出る | `TableControls`の行列追加／末尾削除ボタン | 追加はすぐ押せる位置にし、削除は「行・列を削除」を開いて実行。内容がある場合の確認とUndoは維持 |
| 狭い設定欄で文字が折り返され、説明が薄い | 従来238px、幅1150以下205px。`.inspector-note`の低いコントラストと大きい余白 | デスクトップ280px、幅1150以下252pxへ調整。短い説明、一定の入力欄・余白、濃い補助文字。タッチの主要操作は44px以上。小画面では下部に置く既存構成を維持 |
| 基本書式と選択文字の書式が同時に大きく表示される | `Editor`の`TextSelectionControls`と全体書式details | 直接入力中は選択文字／これから入力する文字の書式を優先。ボックス全体の書式は開いて使用。上下揃え等の機能は残す |
| 範囲選択モードを終えず別の設定へ進める | `cellRangeMode`が設定切替と独立 | 表全体・配置・リンクへ進むと範囲モードを終了。セル範囲自体は保持。セルへ戻れば再選択可能 |
| 設定ボタンにフォーカスしたDeleteが要素／セルを消す | `App`の削除キーと`Editor`の範囲消去がボタン対象にも働く | 設定欄でのDelete／Backspace・範囲貼り付けを編集操作に流さない。キャンバス上の範囲消去・貼り付け、IME保護は維持 |

## 操作の基準

- スライドの文字・セルへの入力はキャンバスで行う。サイドバーは設定用。
- 選択していない対象の設定を同時に見せない。
- 見た目、配置、ページの移動先を別の目的として示す。リンク設定済みはタブにも印を付ける。
- 説明文を全部読むことを前提にせず、短いラベルと選択状態を優先する。
- タブは矢印キー・Home／Endで操作できる。閲覧権限でもタブ移動は可能だが、変更する設定・複製・削除は権限で無効にする。
- データモデル・保存形式・共同編集プロトコルを変更しない。データ消去や旧ファイルの移行を必要とする見直しではない。

## 今回で完了扱いにしない事項

今回の重点は編集画面。アプリ全体のUX問題がすべて解消したという判定ではない。

1. **実端末での入力とタッチ**：Chromebookの日本語IME、iPad Safariのソフトキーボード、Windows実タッチパッド、児童による操作観察は未確認。画面サイズの代替試験と分ける。
2. **長い文章がセルに収まらない場合の案内**：入力・内部スクロールは保つが、発表・PDFに収まらない分を警告する機能は未実装。表を大きくする／文字を小さくする判断をより伝えやすくする余地がある。
3. **グラフの情報量**：`ChartGraphic.tsx`では最大12項目に対しラベル・凡例の表示幅が固定。長い日本語名や多数の値を使った読みやすさは追加検証・改善が必要。
4. **書式の混在表示**：`TableCellControls`は複数セルの先頭の書式を設定欄に表示する。混在状態の明示は未実装。誤解を減らす次の改善候補。
5. **小画面の設定位置**：今回も下部パネル。キャンバスと設定を同時に広く使うには限界があり、実利用でボトムシートとの比較が必要。
6. **全体マップ・クラウド画面との一貫性**：編集サイドバーの改善を、そのまま別画面へ適用したわけではない。作品一覧・共有・フィルタの導線を含むアプリ全体の利用者テストを別に行う必要がある。

## 検証

最終実行の結果を末尾へ記録する。テストは既存の挙動を削って合格させるのではなく、新しい設定タブへの操作を追加。範囲消去の試験は、設定欄にフォーカスした状態で消去する旧期待を変更し、キャンバスでの消去と設定欄で消去しない安全性を別々に確認する。

### 実行結果（2026-10-25）

| 検証 | 結果 | 範囲 |
| --- | --- | --- |
| 本番用ビルド | 成功 | フロント・Node型検査、Vite。既存の500KBチャンク警告は残る |
| `npm test` | 単体119件・Node API16件 合格 | 保存・認可・安定軸・バックアップ・共同編集データ・バージョン等の既存基盤 |
| ローカルの対象ブラウザ回帰 | 72件 合格、16件スキップ | `app`、`content-editing`、`editor-inspector-ux`、`object-editing`、`structure-editing`、`element-stacking`、`element-border-drag`、`tables`、`editor-swipe`。desktop／タッチで実行 |
| Node共同編集ブラウザ | 8件 合格 | 文字・セル書式・画像・図形・グラフ・表、本人Undo、閲覧専用化、範囲別権限、ZIP復元 |
| Cloudflare共同編集ブラウザ | 8件 合格 | 同じ4ファイルをローカルMiniflareの独立作品で実行 |

16件のスキップは、タッチ専用操作をdesktopで、タッチパッド／ネイティブドラッグ／PC画面専用操作をtouchで実行しない対象外条件。全ブラウザテストを一括で実行したという意味ではない。静的プレビューで`/api/config`・`/api/session`の接続拒否が出るケースは、バックエンドを立てずに端末編集を検証する既存試験による。共同編集は別のローカルサーバーを使用。

大きい回帰試験の後に、タッチの範囲選択ボタンへ44pxの指定が確実に効くようCSSの優先順位を修正。最終ビルドでUI/UX専用8件を再実行してすべて合格。主要ボタンと範囲選択ボタンのタッチ44px以上も確認し、別ログへ保存した。変更は表示サイズのみで、データ形式・認可・同期・APIの仕様変更はない。
