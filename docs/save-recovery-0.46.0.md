# 0.46.0：保存・復旧の導線整理（UI/UX改善C）

2026-10-26。0.43.1を基準とした設計の段階C／T07を実装。段階A・Bと0.45.xのマップ操作を維持し、保存先と保存対象を区別する。

## 利用者に見える変更

- 主ボタンを「ファイルに保存」に変更し、ログインなしで編集用JSONを作る既存の1クリック操作を維持。保存メニューにはJSON、PDF、完全バックアップ・復元、保存した版を並べた。
- 上部から専用の「完全バックアップと復元」ダイアログへ直接到達する。既存の`BackupPanel`を再利用し、未完了ジョブの再開・取り消し、画像・付箋・権限の確認、新規作品への復元を維持。クラウド作品一覧からの従来の入口も残す。
- JSON／PDF／ZIPの含む情報を、展開できる説明に表示。JSONは全シートのページ・写真・見出し・ルート、PDFは選択ページの見た目、ZIPはページ・写真・付箋・共有設定。JSONに付箋・共有設定・過去の版は含めない。ZIPにも招待リンク・認証情報・過去の版は含めない。
- 未ログイン・端末作品・参加者には、ZIPを作れない理由を画面に表示する。クラウドのホストでも本文・付箋が未保存ならZIPを作れない。
- JSON／ZIP生成後は「ファイルを作成しました。ダウンロード先を確認してください」と案内する。OSのファイル保存完了を観測したという意味の通知をやめる。
- 既存の上部表示に本文・付箋を含む保存状態を組み込む。本文だけのACKを、付箋も保存済みという表示にしない。付箋の失敗時は件数と再試行ボタンを出し、再読み込みしないよう案内する。平常時に常設のヘッダー行を増やさない。

## 付箋の状態と回復

`src/cloud.ts`に読み取り用の`saveSnapshot`を設け、本文の接続・送信状態、付箋の送信中・失敗・下書きを分けた。`src/saveState.ts`が状態から文言と強調度を決め、`SaveState.tsx`を上部・クラウドの状態表示・バックアップ画面で共有する。復旧が必要→保存エラー→再接続／保存中→保存済みの順で説明する。

`SlideComments.tsx`は、最新の未保存値をCloudWorkspace内へ登録する。ページ移動でエディタが閉じられても失敗した保存処理を保持し、上部から再試行できる。同じ付箋へ戻ると最新の下書きを表示し、再マウントしたエディタの保存処理を優先する。付箋IDごとの送信キューで古い要求と新しい要求を順に処理し、古い応答では新しい下書きを消さない。

- 再試行するPUTの内容は最新のエディタ／保持した下書きから取得し、失敗要求に残った古い本文をそのまま再送しない。
- アカウント・作品・付箋IDに対応を持たせる。他のアカウントへ変わった場合、旧アカウントで送信待ちだった処理を新しい認証で実行しない。
- 削除の応答だけが失われた場合などは、権限付きの付箋一覧でそのIDが存在しないことを確認してから完了とする。失敗したDELETEを無条件に成功扱いにはしない。
- 初回送信に失敗した付箋を空にした場合、古い失敗本文を再投稿しない。サーバーに存在するかを確認し、必要な削除を行う。
- 同じ色を選び直す等の無変更操作、保存済み値へ戻した操作で、未保存フラグが残ってZIPを永久に無効にしない。
- 未保存付箋を残して新規作品／端末作品へ切り替える操作は中止して説明する。ユーザーが別のクラウド作品を開く場合とサインアウトにも、付箋の保存確認を通す。既存のキャッシュ保護の再試行・サーバー指示による復旧を妨げない条件に分ける。

**下書きの保証は、この画面を開いている間のメモリ保持。ブラウザの更新・終了・端末故障に耐える新たな永続保存ではない。** JSONには付箋がないことを表示し、ネットワーク障害中にJSON保存だけで付箋も保護されたと案内しない。

## バックアップの安全性と互換性

ZIP version 1、WorkerでのZIP処理、Room／Directoryのリビジョン検証、ZIP配布直前の再検証、冪等な復元ジョブ、再読み込み後のジョブ発見、新規作品への復元、共有権限を既定で復元しない仕様を変更していない。0.36.1以降の軸ID・権限も維持する。サーバーAPI・DB・認可の変更はない。
