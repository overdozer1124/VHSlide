# 実 Google 認証と検証用 Cloudflare DO の独立試作（2026-11-01）

対象は検証専用 Worker `vhslide-stage1-verify-20261101-a`、DO 名前空間 `ef29957c85744eccaea6db64af433868`、インスタンス `stage1-verification-only-20261101`（`bf5225d37ca48b7ada421746c70e542d41f3ca128b4cb75ff0b1775400ea8f48`）。実行前に Cloudflare の名前検索と実行時応答を独立に照合し、試作用 `gtrial_*` テーブルが存在しないことを確認した。公開ルートは作らず、ローカルの remote service binding を利用した。

異なる２つの Google ID トークンをローカルと Worker 側でそれぞれ Google tokeninfo を使って検証し、aud・iss・exp・nonce・email_verified と sub の存在を検査。ユーザー申告により指定２アカウントを使用した。運営キーと復旧キーは別々に生成し、復旧には両方を要求した。識別子はテスト用の一時的な秘密塩で HMAC に変換して DO に保存し、ID トークン・生の sub・メールは保存・ログ出力しない。

結果は、誤運営キー 403、初代登録 201、再登録 409、復旧前の旧 ID トークンによる操作 200、誤復旧キー 403、正しい復旧 201、復旧後の旧 ID トークンによる操作 403、新 ID トークンによる操作 200。Data Studio からの独立読取で、有効資格・登録完了記録・復旧記録が各１件だった。

使用後、運営キー・復旧キー・識別子用の塩を削除し、`wrangler secret list` が空であることを確認。ローカル中継と認証サーバーを停止し、Worker は受付機能のない初期コード（バージョン `26a4b52d-6001-40a3-ace4-eda9fe221b83`）に戻した。試験の HMAC 化された識別子と登録・復旧記録は検証専用 DO に保持している。塩は削除済み。

制約：ここで再利用して拒否したのは ID トークンであり、製品の既存セッションではない。２つのキーは独立した値だが、試験時には同じローカル操作プロセスで扱っており、実運用における独立した運営者認証や喪失時の安全な復旧手順の実証ではない。Google ID と本番 users の対応、Cloudflare での失敗注入・並行実行を実認証と組み合わせた試験、再起動後の一貫性、CSRF・Origin を含む実運用経路の保護は未検証。この試作を A 群全体や製品受入の合格としない。

## 追加試験：並行・途中失敗・DO 再起動

別の試作用テーブル `gtrial2_*` の初期状態が空であることと、Worker・DO・インスタンスを実行前に照合。実 Google ID トークン２件を Worker 側で検証したうえで、登録途中の意図的失敗後に資格がないこと、２件の並行登録で成功１件・拒否１件、復旧途中の意図的失敗で旧資格が維持され新資格が付かないこと、復旧後に旧 ID トークンが拒否され新 ID トークンが許可されることを確認した。

意図的に DO を `abort` で再起動し、メモリー内の起動識別子が変わったことと、その後も旧 ID トークンの拒否、新 ID トークンの許可、再登録拒否が継続することを確認。Data Studio でも有効資格・完了記録・復旧記録が各１件。これは試作の保存状態についての実証であり、製品セッションの失効や実運用の運営者認可を示さない。

３つの一時キーは削除され `secret list` が空と確認。中継を停止し Worker を受付機能のないバージョン `6d33f382-a543-4c15-bec6-7cc90efde9cb` に戻した。塩を削除済みの HMAC 化識別子と試験記録は検証専用 DO に保持する。上の「未検証」のうち実認証と組み合わせた並行・失敗注入および意図的再起動の項目はこの試作で確認済み。製品に対する確認、実セッション、実運用の運営者認可と CSRF・Origin の保護は引き続き未検証。
