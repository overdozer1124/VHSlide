# VHSlide

「よこに話題を、たてに発見を。」児童・生徒のための、2次元グリッド型スライド作成・発表アプリのMVPです。React 19 / TypeScript / Vite / Tailwind CSS 4 を使用し、端末だけで編集・JSON保存・発表できる構成に加え、RailwayまたはCloudflare上でGoogleログイン・作品保存・共同編集を使える構成を備えています。

従量課金を避けてCloudflareの無料枠で停止させたい場合は、[Cloudflareの構築手順と無料枠の制限](docs/cloudflare.md)を参照してください。R2を使わず、写真もSQLite型Durable Objectsへ保存する構成です。Workers Freeの利用が前提です。

## 自由配置の回答欄と回答スライド

ツールバーの「フォーム」がアンケート・ワークシートの共通入口です。共有作品のホストは「回答欄を追加」タブから入力欄を配置できます。回答は自動保存され、共通モーダルの「回答スライド」タブから、スライドの見た目を保った一覧を共有できます。作成・自動保存・共有範囲の詳しい動作は[自由配置の回答欄](docs/design/free-worksheet-inputs.md)を参照してください。

## 起動

Node.js 24（この環境では24.19で検証）とnpmを使用します。

```sh
cd /workspace/VHSlide
npm ci
npm run dev -- --port 5173 --strictPort
```

一般のPCではチェックアウトしたディレクトリ内で同じnpmコマンドを実行してください。最初は編集できるサンプル作品を表示します。「新しく」で白紙から作成できます。

```sh
npm run build          # TypeScriptチェック + 本番ビルド
npm run preview       # ビルド済みdistの動作確認
npm test              # 座標・JSON・共有データ・サーバー権限・40接続のテスト
npm run test:e2e      # デスクトップ/iPad相当のChromiumブラウザテスト
```

E2Eテストはシステムの `/usr/bin/chromium` があれば利用します。その他の環境では事前に `npx playwright install chromium` を実行してください。ブラウザの場所は `CHROMIUM_PATH` でも指定できます。

`dist/` 一式を静的ホスティングに配置できます。相対パスでビルドするため、サブディレクトリへの配置にも対応します。ローカル配布時も静的HTTP配信を使ってください（HTMLのダブルクリックによる `file://` 起動は対象外）。静的配信ではブラウザだけで作成・保存・発表でき、Googleログインや共同編集は表示しません。Railwayでサーバーを動かす場合は、Googleとクラウド保存への通信を利用します。完全なオフライン再起動を保証するPWAのキャッシュ機能は未実装です。

## RailwayでGoogleログイン・共同編集

[Railway設定手順](docs/railway.md)に、新規プロジェクト・永続Volume・Google OAuthクライアントID・写真用Bucketsの設定をまとめています。`railway.json`でビルド・起動・ヘルスチェックを設定済みです。GoogleクライアントID未設定でも端末の編集機能は利用できます。

```sh
npm run build
npm start             # Node.jsサーバー。既定は3000番
npm run test:cloud    # 本番ビルドを使う共同編集のブラウザテスト
```

サーバー側ではYjs/WebSocketで変更を共有し、SQLiteの更新ログへ保存します。写真はRailway Buckets（未設定時は永続ディスク）に保存します。招待による参加・参加解除・作品ごとの画像アクセス制御に対応しています。静的ホスティングのGitHub Pagesは、従来の端末編集用として引き続き利用できます。

## GitHub Pagesで公開

[Settings → Pages](https://github.com/overdozer1124/VHSlide/settings/pages) の **Build and deployment → Source** を **GitHub Actions** に設定します。その後 [Deploy GitHub Pages](https://github.com/overdozer1124/VHSlide/actions/workflows/pages.yml) を開き、**Run workflow → main → Run workflow** を実行してください。以降は `main` へのpushごとにテスト・ビルド・公開が自動で実行されます。

デプロイ成功後の標準URLは **https://overdozer1124.github.io/VHSlide/** です。公開状態と実際のURLはGitHubのPages設定画面・Actionsの `deploy` ジョブで確認してください。

ワークフローはNode.js 24で `npm ci`、`npm test`、`npm run build` を実行し、`dist/` のみをPagesに配置します。GitHub公式のPages Actionsを使用し、追加のアクセストークンは不要です。Viteの相対パス設定 `base: "./"` を使用するため、`/VHSlide/` のようなサブパスでも画像・JavaScript・CSSを読み込めます。

ローカルと公開サイトの自動保存はブラウザの別の領域です。ローカルの作品を使う場合は、JSONで保存してから公開サイトで「開く」を選んで読み込んでください。

## Windows（PowerShell）での起動

`/workspace/VHSlide` はCodexのクラウド内のパスであり、Windowsのパスではありません。ソースがGitHubに反映された後、PCで以下を実行して取得してください。Node.js 24とGitが必要です。

```powershell
git clone https://github.com/overdozer1124/VHSlide.git "$env:USERPROFILE\VHSlide"
Set-Location "$env:USERPROFILE\VHSlide"
Test-Path .\package.json
npm ci
npm run dev -- --port 5173 --strictPort
```

同名フォルダーがすでにある場合は、別のクローン先を選び、既存のファイルを上書きしないでください。Gitを使用しない場合はGitHubの「Code → Download ZIP」で取得・展開し、`package.json` があるフォルダーに移動してからnpmコマンドを実行してください。

`Test-Path` が `True` になる場所でnpmを実行します。起動後、PCのブラウザで `http://localhost:5173` を開いてください。停止はPowerShellでCtrl+Cを押します。`Missing script: "dev"` は、別のフォルダーでnpmを実行している場合や、実装したソースがPC側にない場合に発生します。

## 使い方

- **アカウントの事前共有**：「クラウド」→「共有するアカウントを追加」でGoogleアカウントのメールアドレスをまとめて貼り付けます。改行・カンマ・空白区切りや「名前 <メールアドレス>」に対応し、大小文字違いを含む重複は先頭の1件にまとめます。初期設定では選んだシート・開始行から、貼り付け順に1行ずつ編集権限を割り当てます。既存の割り当てがある場合の開始行はその続きです。保存前のプレビューで宛先と行番号を確認できます。「全員に同じ編集権限を設定する」では、閲覧のみ・全スライド・任意の行／列／スライドの設定も使えます。未作成の行にはスライドを作らず、その位置に後で追加したページへの権限だけを予約します。100行を超える一括割り当ては途中まで登録せず停止します（1回100アカウント・作品全体500アカウントまで）。
- **招待リンクの承認制（0.39.0）**：未登録の人がリンクを開くとホストへの参加申請になります。ホストは「クラウド」→「共有管理」の参加待ち一覧で氏名・メールを確認し、個別、チェックした相手、全選択から承認できます。承認前は作品・画像・付箋を取得できません。承認後は作品全体の閲覧・保存と付箋コメントが可能になり、編集範囲は別に設定します。作品一覧の参加待ち人数からも確認できます。共有解除後の再参加も再承認が必要です。申請は24時間有効で、リンクを作り直す／無効化すると未承認の申請も失効します。ホストが事前共有した人と既存参加者は追加承認不要です。[設計・検証](docs/invitation-approval.md)
- **事前共有からの参加**：メール通知は送りません。「事前共有した作品のリンク」を伝えるか、従来の招待リンクを使ってください。サインイン時のGoogle認証で確認済みのメールアドレスと照合し、事前の権限を本人のアカウントへ適用します。未参加の相手も先に登録でき、招待リンクがなくてもサインイン後の作品一覧に表示されます。既にサインインしている場合は「作品一覧を更新」を押すか、作品リンクを開いてください。登録するのはGoogleから確認される本人のメールアドレスで、別名アドレスやメーリングリスト・グループへの共有は対象外です。登録順の一覧で参加待ち／参加済みを確認し、参加前後とも権限変更・共有解除ができます。既存のアカウントを再登録するとプレビューした権限へ更新します。
- **共有の権限**：クラウド作品の作成者がホストです。「クラウド」→参加者一覧の「編集権限を設定」で、閲覧のみ／すべてのスライド／指定範囲を選べます。範囲はシートごとの行・列見出しや個別のページ番号をクリックして選択し、「権限を保存」で反映します。複数の指定は合算されます。参加者一覧にまだ表示されない場合は「参加者一覧を更新」を押してください。既存・新規とも未設定の参加者は閲覧・コメントのみで、ホストが明示的に編集範囲を割り当てます。ホストは全ページ・作品名・シート管理・招待・権限設定を操作でき、クライアントは作品名やシートの設定を変更できません。権限はサーバーにも保存し、WebSocketでの本文編集・削除・移動にも毎回検証します。範囲外へ影響する一括操作は全体を拒否します。行・列の指定は安定した行・列ID、個別指定はスライドIDに紐づきます。行・列を並べ替えても担当範囲は元の行・列に追随します。権限の変更時は取り消し履歴をリセットし、変更前の範囲を後から書き換えることを防ぎます。
- **付箋コメント**：クラウド作品の編集画面で上部ツールバーの「付箋」を押すと、スライド上に付箋が現れ、その中に直接入力できます。入力は自動保存され、上部の移動ハンドルをマウス・タッチでドラッグして位置を変えられます（ハンドルの矢印キーでも移動可能）。投稿操作は不要です。編集できないページにも、コメントが許可されていれば付箋を投稿できます。本文は変えず、参加者名とともに共有・永続保存します。投稿者本人またはホストが編集・移動・削除でき、ホストは参加者ごとにコメント投稿をオン／オフできます。上限は1件1000文字・作品全体2000件です。付箋と権限はクラウド作品の別データとして保存し、発表やスライドJSONには含めません。
- **ページ番号**：「縦.横」（段番号.その段の横位置）で表示します。例えば3行目の2枚目は `3.2` です。左の縦一覧・横一覧・全体マップ・編集画面・発表時の現在地で共通です。
- **全体マップ**：カードを押すと編集。右の＋で新しい話題、下の＋で詳しいページを挿入します。空のマスにも直接追加できます。
- **マップの表示サイズ**：マップ内を縦横にスクロールできます。初期設定は「100% → 60% → 番号一覧」です。倍率設定ボタンから `30, 80, 120` や `80, 100` のように10〜300%の整数を入力し、倍率と段階数を自由に変更できます。小さい順に並べ、重複を除きます。−／＋とピンチは設定した順に切り替わり、最小倍率の手前は番号一覧、最大倍率の次のピンチアウトで編集画面へ移ります。「横をおさめる」は設定倍率から画面幅に収まる最大値を選びます。倍率表示を押すと100%（含まれない場合は最も近い設定倍率）に戻ります。編集画面から戻ると倍率を保ち、編集中だったページをできるだけマップの中央に表示します。端にある場合はスクロールの端で止まります。
- **マップのフィルタ**：「フィルタ」を押すと、マップ上の行・列の見出しや実際のスライドをクリック／タップして選択できます。選択したページにはチェックと枠が付き、行・列をまとめて選んだあと特定の1枚だけを外すこともできます。「フィルタを適用」で、4枚なら2×2など縦横の偏りを抑えて並べます。元の配置・番号を変えず、ズーム・番号表示・ピンチによる編集画面との行き来も使えます。「キャンセル」は適用前の表示を保ちます。
- **編集画面のフィルタ**：「編集画面にもフィルタを適用」は初期状態でオンです。左のサムネイルと横一覧には対象ページだけを表示し、矢印キー・スワイプ・タッチパッドでも対象の間だけを移動します。編集ツールバーのフィルタボタンからいつでもオン／オフを切り替えられ、オフでもマップの絞り込みは保ちます。対象外のスライドは作品内に残り、保存・共同編集の対象から消えません。絞り込み中の行移動・行単位の一括操作・空きマス追加は表示せず、枠の操作が対象外のページに及ばないようにしています。フィルタは利用者ごと・シートごとの一時的な表示設定です。

- **シート**：画面下のタブで独立したスライド一覧を切り替えます。「＋」で空のシート、「…」で複製・名前の変更・削除・左右への並べ替えができます。空のシートは白紙のページ1枚から始まります。シートは最大50枚、作品全体でスライド1000枚までです。JSON保存・読み込み・自動保存・共同編集に対応し、表示中のシートは各利用者が独立して選べます。変更は「もとに戻す」に対応します。従来の作品は「シート1」として開きます。
- **シートタブの操作**：ダブルクリック（またはF2）でタブ上の名前を編集します。Enterまたは別の場所をクリックして確定、Escで取り消せます。右クリックでそのシートのメニューを開き、複製・削除などを操作できます。タブを左右へドラッグすると挿入位置の線が表示され、離すと順番を変更します。タッチは長押し後にドラッグ、横スクロールは通常のスワイプです。「…」のメニューと左右移動ボタンも使えます。名前・順番の変更は編集中のスライドを保ち、保存・共同編集・元に戻すに対応します。
- **段を指定数複製**：編集画面の左の段の「…」から「複製する段の数」を入力し「指定数の段を複製」を選ぶと、元の段の直下へ同じ内容をまとめて作成します。既存の下の段は後ろへ送られます。1操作で取り消せ、ページ数・100段の上限を超える場合は途中まで作らず通知します。
- **表示設定の保存**：倍率の段階、サムネイルバーの幅・行番号一覧の表示と左右バーの開閉は、このブラウザの個人設定として保存します。共同編集相手の表示や、作品のJSONデータには影響しません。
- **マップと編集のピンチ切り替え**：マップ上で2本指を広げると、指の中心のページを拡大し、広げ始めて指を離すと編集画面へ滑らかに切り替わります。編集中に2本指を閉じて離すと、そのページのマップへ戻ります。拡大・縮小の開始方向が決まったら、途中で指を戻してもその方向の切り替えを最後まで完了します。2本指を置くだけの操作やごく小さな揺れでは切り替わりません。対応するタッチパッドのピンチ（ブラウザのCtrl＋ホイール形式）でも操作できます。上部の切り替えボタンも使えます。
- **番号一覧**：いちばん小さい設定倍率からさらに縮小すると番号だけのマップになります。「#」でも切り替えられます。いまのページは濃い色で表示し、照準ボタンで中央に表示します。「3.2」のような番号で検索すると、そのページを選んで表示します。番号をクリックすると編集できます。番号は縦.横で、作者や所有者を示すものではありません。
- **大量ページの描画**：画面内とその周辺だけに文字・図形・画像を描画し、画面外は固定サイズの軽い枠で位置を保ちます。スクロールすると必要なサムネイルを描画し、番号一覧ではスライド内容を描画しません。マップは編集中には非表示にして更新を止め、復帰時に作り直さず再利用します。ピンチ開始時も全ページの画面座標を読み取らず、触れたページまたはグリッド座標から対象を選びます。
- **並べ替え**：カードを別のカードに重ねると入れ替え、横のカード間に置くとその段へ挿入します。挿入先ではカードが横にずれ、「ここに挿入」と表示します。タッチはカードを約0.3秒長押しして移動、移動用のつまみからはすぐにドラッグできます。通常のスクロールと2本指のピンチも使えます。カードの移動ボタン→移動先をタップする方法でも操作できます。話題の見出しのハンドルは縦一列、左の番号は横一列をまとめて移動します。空白への移動も整数マスに限定します。
- **編集**：文字・画像・図形を追加し、キャンバス上で移動・リサイズします。文字は枠をクリックして直接入力し、右のパネル（小画面では下）はサイズ・太字・色などの書式設定に使います。新しい文字ボックスは追加直後にそのまま入力できます。日本語IME、改行、文字の貼り付けに対応し、入力中の矢印は文字カーソルを動かします。EscまたはCtrl/Cmd+Enterで文字編集を終了します。文字・図形・画像・表の外枠をドラッグすると移動し、右下の点でリサイズします。
- **文字の位置**：文字を選び、右の書式パネルの「左右の位置」で左・中央・右揃え、「上下の位置」で上・中央・下揃えを選べます。テキストボックスの枠の位置や大きさは変えず、中の文字だけをそろえます。入力中・サムネイル・発表でも同じ配置になり、JSON保存と共同編集に反映されます。従来の作品は左上揃えで開きます。
- **編集画面の整理（0.43.1）**：右の設定を「見た目・配置・リンク」、表を「セル・表全体」に整理。複製・削除を上部にまとめ、セルのスクロールバー矢印をなくして余白からも入力できます。[改善内容と残る課題](docs/editor-ux-review.md)。
- **図解・グラフ・作品内リンク（0.43.0）**：グループ化と追従する接続線、編集できる比較・手順・時系列の図解、棒・折れ線・円グラフ、別ページへのリンクと発表中の戻る操作に対応。[使い方・保存・検証](docs/structure-editing.md)。
- **図形・線・まとめて配置（0.41.0）**：25種類の図形をカテゴリ別に選び、図形内へ直接文字を入力できます。直線・両矢印・折れ線・曲線は両端の丸で向きを調整します。Shiftクリックや「まとめて選択」で複数の要素を選び、外枠から一括移動・複製・削除・整列ができます。回転・反転・比率固定等は右側の「サイズ・向き」へまとめています。[操作・互換性・検証](docs/object-editing.md)、[段階的な開発計画](docs/object-editing-roadmap.md)。
- **写真・文章・表（0.42.0）**：画像はプレビューで切り抜き・位置調整し、位置を保って差し替えできます。文字は範囲を選んで書式を設定し、段落の番号・行間も変更可能。表はセル／範囲の書式、選択位置での行列操作、列幅・行高、Excel等からの貼り付けに対応。[操作・制約・検証](docs/content-editing.md)。切り抜きは元画像を保持するため、個人情報の除去には事前の画像加工が必要です。
- **編集領域を広げる**：編集ツールバーの左右のパネルボタンで、サムネイルバーと書式のサイドバーを個別にたたみ、同じボタンから戻せます。両方をたたむと余白と補助表示も減らし、キャンバスを最大表示します。スライドの文字・画像・図形の座標は変わりません。
- **サムネイルバーの幅**：左バーの右端をドラッグすると、画面サイズに応じた標準幅の80〜150%で調整できます。サムネイルは16:9を保って幅に合わせて拡大・縮小します。境界のダブルクリックで100%に戻ります。境界にキーボードフォーカスを置くと左右キーで5%ずつ、Homeで80%、Endで150%に変更できます。
- **行番号からジャンプ**：編集画面の左バー上部の「行番号一覧」で、サムネイルを複数列の行番号に切り替えます。番号をクリック／タップすると、その行で選択済みのページへすぐ移動し、現在の行を色で示します。もう一度押すとサムネイル一覧に戻り、選択した行を自動で表示します。フィルタ中は対象の行だけを元の番号で表示します。空の行は薄く表示し、ページを作成しません。
- **編集画面の縦横サムネイル**：左のバーには、段ごとに選んだサムネイルを表示します。各段にマウスを180msほど乗せると、その段の全話題を右へ展開します。タッチ端末はタップで展開。初期状態では、横一覧からページを選ぶと、その段の左サムネイルだけを更新します。各段の選択は自動保存・JSONにも保存されます。空の段・マスも元の位置に残り、マスを押すとページを作成できます。展開表示はキャンバスに重なり、編集領域の大きさを変えません。長い横一覧は内部で横スクロールします。
- **縦の連動**：編集ツールバーの「縦の連動」でいつでもオン／オフを切り替えます。オンでは、編集中のページと同じ話題（同じ横位置）を各段の左サムネイルに表示します。その位置にページがない段は空のマスとして表示し、上下キーでは同じ話題の存在するページへ移動します。オフに戻すと、連動前の各段の選択を復元します。設定は自動保存・JSONにも保存され、従来の作品はオフとして開きます。発表時のナビゲーションは従来どおりです。
- **サムネイルのメニュー**：全体マップ・横一覧のサムネイルを右クリックすると、そのページの複製・削除ができます。左の縦サムネイルでは、表示中のページの操作に加え「この段をまとめて複製／削除」で横につながるグループ全体を一括操作できます。タッチ端末では各サムネイルの「…」から同じメニューを開けます。個別の複製は同じ段の右隣に挿入し、その段だけ右へ送ります。グループの複製はすぐ下に挿入し、それより下の段を送ります。グループ削除は下の段を詰めます。いずれも「もとに戻す」で1操作として取り消せます。メニューは上下キーで選択、Enterで実行、Escで閉じられます。
- **サムネイルのドラッグ移動**：左のサムネイルを上下へドラッグすると、同じ段のページをまとめて移動します。別の段に重ねると段を入れ替え、段の間に置くと挿入して間の段を送ります。横一覧のサムネイルは1枚ずつ、別の段・別のマスへ移動できます。別の段の左サムネイルの上で少し待つと、その段が展開するので移動先のマスへドロップしてください。空白なら移動、既存ページに重ねると2枚を入れ替え、横のページ間なら挿入します。挿入では移動元の段を詰め、移動先の段だけを右へ送り、ほかの段の並びは変えません。挿入先では隣のサムネイルがずれて置き場所を示します。ドラッグ中の末尾の「新しい段へ」へもドロップできます。タッチ端末は約0.3秒の長押し後にドラッグします。サムネイルのつまみからはすぐに移動を開始でき、長押し中の小さな指の揺れにも対応します。Escでキャンセルし、移動後は「もとに戻す」も使えます。開始マス `(0,0)` が空になる移動は受け付けません。
- **編集ページの矢印移動**：サムネイルを選んだ後、左右矢印で同じ段の前後のページ、上下矢印で別の段の選択済みページへ移動します。横一覧が閉じた後も移動可能です。文字入力やキャンバスの要素操作中はページ移動に使いません。
- **編集ページのスワイプ移動**：文字・画像・図形の上でも1本指でページを移動できます。ページと隣のページが指に追随し、指を止めれば途中で止まり、元の位置に戻せばページも戻ります。十分に動かして離すとスライドして切り替わります。左へ払うと右のページ、上へ払うと下の段へ移動し、「縦の連動」にも従います。移動先がない場合や操作を中断した場合は元へ戻ります。タッチパッドはスライド上で2本指のスクロール操作を使います。タッチ時の要素操作はタップで選択・文字入力、外枠で移動、右下のハンドルでサイズ変更です。マウスは従来どおり要素を直接ドラッグできます。
- **コンパクトな編集画面**：作品ヘッダーと編集ツールの2段に整理し、取り消し・使い方も編集ツールの段に配置しています。Chromebookの1366×768、1280×720では上部は約92pxです。
- **編集画面からの挿入**：横一覧のページ間・末尾の＋で列を挿入し、右側の話題を詳細ページごと移動します。左一覧のページ間・末尾の＋で行を挿入し、全話題の下側のページをまとめて移動します。押した位置に白紙1枚を作って、そのまま編集します。
- **横一覧を閉じる**：マウスで一覧から離れると少し待って閉じます。外側のクリック・タップ、閉じるボタンでも閉じられます。キーボードでは左の段にフォーカスし、右矢印・Enter・Spaceで横一覧へ移動、Tabで選択、Escで閉じて元の段に戻れます。
- **画像**：ファイル選択、キャンバスへのドロップ、Ctrl/Cmd+Vの貼り付けに対応。PNG / JPEG / WebP / GIFを作品内に埋め込みます。
- **発表**：必ず `(0,0)` から開始。矢印キー、画面の矢印、スワイプで移動。左右には次・前の話題、上下には同じ話題の詳しいページへ移動します。スライドは16:9を保って画面内に最大表示し、操作のための上下の余白は設けません。マウスを画面の上下端に近づけると、終了・全画面・移動ボタンと現在地マップを重ねて表示し、離すと隠します。タッチ端末は画面のタップで表示し、キーボード操作やフォーカスでも操作表示を使えます。終了ボタンまたはEscで戻ります。
- **保存**：「保存」で作品全体をJSONダウンロード。「開く」で画像を含めて復元します。変更はこのブラウザのLocalStorageにも自動保存されます。授業の終わりにはJSONも保存してください。
- **取り消し**：削除、移動、新規作成、ファイル読み込みも「もとに戻す」で取り消せます。ローカル作品は最大40操作。共同編集では、このブラウザで行った自分の変更だけを取り消し・やり直し、相手から受け取った変更を履歴に含めません。同じ文字ボックスの共同編集にも対応します。作品を開き直すと共同編集の取り消し履歴はリセットされます。Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Zにも対応します（文字入力中はブラウザ標準の取り消し）。

表示確認用に [横10枚 × 縦40枚のサンプルJSON（400枚）](public/samples/vhslide-10x40.json) を用意しています。ファイルをダウンロードし、アプリの「開く」から読み込んでください。列ごとに色・テーマが異なり、各ページの「行.列」番号で位置を確認できます。外部画像への接続は不要です。

## アーキテクチャ・コンポーネント

状態はReact内の1つの `Deck` に集約します。マップ・編集・発表の3画面が同じデータと描画コンポーネントを参照するため、サムネイルと発表で要素の位置が変わりません。座標操作・検証を純粋関数として分離しています。

```text
src/
  App.tsx                 画面切替、作品状態、履歴、自動保存、JSON・画像の入出力
  MapView.tsx             固定間隔グリッド、追加、単体・横一列・縦一列の移動
  MapZoomSettings.tsx     マップの倍率と段階数を設定
  workspacePreferences.ts 表示設定の検証・ブラウザ保存
  Editor.tsx              編集ツール、ページ一覧、書式・整列パネル
  EditorPager.tsx         編集ページと隣接ページのスライド表示
  useSlidePan.ts          指に追随するページ移動、タッチパッド、戻り・確定の制御
  usePinch.ts             2本指・タッチパッドのピンチ検出と操作の分離
  WorkspaceTransition.tsx マップと編集をスライドの拡縮でつなぐ表示
  SlideRail.tsx           固定幅の縦一覧、段ごとの横展開、行・列の挿入
  Canvas.tsx              共通の16:9描画、Pointer Eventsでの移動・リサイズ、ガイド
  InlineText.tsx          キャンバス内の直接入力、IME・プレーンテキスト貼り付け
  RailDrag.tsx            段・単体ページのドラッグ、入れ替え・挿入のドロップ先
  useMapTouchDrag.ts       マップの長押し・つまみ移動、端でのスクロールとピンチの分離
  ThumbnailMenu.tsx       サムネイルの右クリック・タッチ用メニュー
  PresentationView.tsx    方向別アニメーション、タッチ操作、矢印、現在地HUD
  useFitCanvas.ts         ResizeObserverによる表示倍率の計算
  model.ts                型、サンプル、整数マスの操作、段ごとの選択、ナビゲーション、JSON検証

  style.css               Tailwind取り込み、共通デザイントークン、レスポンシブUI
```

端末の作品は画像をData URLでJSON内に保存します。クラウドに保存する場合は作品と写真をサーバーへ送信し、参加者に共有します。クラウド作品のJSONダウンロード時には写真を再びData URLに埋め込みます。LocalStorageのキーは `vhslide-deck-v1`。自動保存の容量超過は通知し、JSONの書き出しは引き続き利用できます。破損した自動保存データを検出した場合、元データを上書きせずサンプルを表示し、明示的な再開操作まで自動保存を保留します。

## データ構造

正式な定義は [JSON Schema](docs/deck.schema.json)、実行時の検証は [model.ts](src/model.ts) にあります。

```json
{
  "version": 1,
  "title": "まちの発見",
  "slides": [
    {
      "id": "slide-start",
      "x": 0,
      "y": 0,
      "title": "はじめに",
      "background": "#e5f0dc",
      "elements": [
        {
          "id": "text-title",
          "type": "text",
          "x": 72,
          "y": 140,
          "w": 800,
          "h": 170,
          "text": "わたしたちのまち",
          "fontSize": 56,
          "bold": true,
          "color": "#173d38",
          "bullets": false
        }
      ]
    },
    {
      "id": "slide-detail",
      "x": 0,
      "y": 1,
      "title": "くわしく",
      "background": "#ffffff",
      "elements": []
    },
    {
      "id": "slide-next",
      "x": 1,
      "y": 0,
      "title": "次の話題",
      "background": "#ffffff",
      "elements": []
    }
  ]
}
```

| 対象                    | 意味・ルール                                                                                                                       |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `Slide.x / y`           | 0以上の整数マス。Xが話題、Yが深掘り。重複不可。スライド自体のピクセル位置は保存しません。                                          |
| マップ表示              | 倍率に応じた固定サイズのマスに整列。ピンチ中はグリッド全体を変形し、指を離してからレイアウトを確定します。各倍率で間隔は一定です。 |
| `Element.x / y / w / h` | 960×540の論理キャンバス内の位置・サイズ。表示倍率を変えても保存値は変わりません。                                                  |
| 要素の前後              | `elements` 配列の後ろほど前面です。                                                                                                |
| `type: text`            | `text`, `fontSize`, `color`。任意で `bold`, `highlight`, `bullets`。書式はテキストボックス単位です。                               |
| `type: image`           | `src` は画像Data URL、または認証付きの作品内画像パス。任意の外部URL・SVGは受け付けません。                                         |
| `type: shape`           | `shape` は `rect / rounded / circle / arrow / bubble`。`fill`, `stroke` は色です。                                                 |
| `version`               | 保存形式のバージョン。現状は1のみ。将来の移行処理の判定に使えます。                                                                |

**挿入・移動・削除の決まり**

- 右の＋は右隣に新しい話題の先頭ページ `(x+1,0)` を挿入し、右側の話題を丸ごと1マスずつ送ります。
- 下の＋は同じ話題の `(x,y+1)` に挿入し、その話題の下のページだけを1マスずつ送ります。
- 編集画面のページ間の＋はグリッド全体に行・列を挿入します。全体マップの下の＋は、その話題だけを掘り下げる従来の操作です。どちらも既存のJSON形式をそのまま使い、保存済み作品を移行せず利用できます。
- 単体・横一列・縦一列の移動はいずれも入れ替え。空のマスを利用する場合も小数座標・自由配置にはしません。
- 発表開始位置 `(0,0)` は常に保持します。開始ページは他のページとの入れ替えが可能ですが、空のマスには移せません。開始ページを削除した場合は次のページを開始位置に繰り上げます。最後の1枚を消したときは白紙1枚に戻します。
- 保存形式v1の任意フィールド `rowSelections` に、各段で選んだスライドのIDを配列で保存します。段の移動時もIDに追従し、削除済みのIDは読み込み時に整理します。以前の作品にはこのフィールドがなくても対応します。
- 任意フィールド `linkedRows` は編集画面の縦の連動設定です。省略時はオフです。連動中の閲覧では `rowSelections` を上書きしないため、オフに戻すと独立した選択を復元できます。複製時はページと要素のIDをすべて新しく生成します。グループ削除で開始マスが空になる場合は、ほかの話題の位置を変えず白紙の開始ページを補います。
- 発表時の左右移動は隣の存在する話題へ。同じ深さのページがなければ、その話題の最上段に移動します。上下移動は同じ話題内の次・前のページへ。空のマスは飛ばします。

**読み込み時の検証**：バージョン、必須項目、IDの全体一意性、整数座標と重複、開始位置、要素の境界・型・画像Data URL・色を検証します。取り込んだ文字列をHTMLとして解釈しません。JSON Schemaで表現しにくい座標の一意性・要素がキャンバスに収まる制約も実行時に検証します。

## MVPの範囲・制限

- 最大1000ページ、各ページ200要素、縦横それぞれ100マス。画像1枚6MB、作品全体25MBまでです。自動保存に使える容量は端末・ブラウザに依存し、この上限より小さい場合があります。
- 太字・色・サイズ・ハイライト・箇条書きはボックス全体への設定です。文字の部分選択による書式、複数要素の同時選択、回転、動画、PDF/PPTX書き出しは未実装です。
- 整列ガイドはキャンバスの水平・垂直中央。近くの他要素への整列ガイドは今後の拡張対象です。
- 全画面APIが使えない環境でも画面内の発表表示を継続します。
- 自動テストはChromiumのデスクトップ・iPad相当表示で実施します。実機のiPad Safari / Chromebook / Windowsでの総合確認は別途必要です。
- 静的配信の端末編集にはキー・認証情報は不要です。クラウド機能にはサーバー・GoogleクライアントID・永続ディスクが必要です。実Googleアカウントと実Railway/Bucketsでの確認は設定後に実施します。

全体マップの列名と行名は、見出しをクリック／タップして直接入力できます。Enterまたはフォーカスを外すと保存、Escで取り消します。行番号・列番号は位置を示すため固定し、その横に付ける名前を編集します。クラウド作品ではホストが見出しを変更でき、参加者には読み取り専用で共有されます。シートごとに保存され、JSON保存・復元、シート複製、自分の変更の取り消しにも対応します。

クラウド作品のマップにある「行に名前」をオンにすると、その行への編集権限を明示的に割り当てた共有相手の名前を縦書きで表示します。参加前はメールアドレスの `@` より前を表示し、参加後はGoogleアカウントの表示名になります。複数人には「・」で区切って表示します。手入力の行名がある場合はそちらを優先し、空欄にすると自動表示に戻ります。共有相手名は作品の参加者だけが参照でき、マップ表示用のAPIにはメールアドレス全体や権限設定を含めません。

サムネイルのフッターは、マップ・編集画面の左の一覧・展開した横の一覧から直接編集できます。Enterまたはフォーカスを外すと保存、Escで取り消します。空欄にすると、そのページに行・列・個別ページ単位で編集権限を割り当てた共有相手の表示名を自動表示します。全体の編集権限を持つ共有相手も含め、ホストは自動表示から除きます。該当する相手がいなければ元のページ名を表示します。手入力した表示名はページ本文や元のページ名を変えず、JSONや共同編集で保存・復元されます。

付箋のパレットボタンから色と「小・中・大」を選べます。右下のハンドルはマウス・タッチのドラッグや矢印キーでもサイズを変更できます。色・サイズは自動保存・共有され、付箋の作成者とホストだけが変更可能です。既存のクラウド付箋はデータを残して見た目の保存項目を追加します。

[更新履歴](https://vhslide.overdozer1124.workers.dev/#updates)は、マップ・編集画面の履歴アイコンから開けます。現在のバージョンは更新履歴ページで確認できます。0.1.0〜0.33.0は開発記録から整理した過去の履歴で、当時に付けていなかった番号を今回割り当てています。以後は機能変更と同時に `src/releaseHistory.ts` とパッケージのバージョンを更新します（開発手順は `AGENTS.md`）。

クラウドの作品は中央の大型画面で管理し、小さい端末では全面表示になります。「作品一覧」では作品名検索・自分／参加作品の絞り込みと「開く」付きのカードを使い、「共有管理」では追加フォームを閉じても共有相手・参加状況・編集範囲を一覧で確認できます。チェックボックスで複数選択すると、共通の権限や一覧順の行割り当て、共有解除をまとめて実行できます。絞り込み中の「すべて選択」は表示中の相手を対象にし、他の選択は保持します。処理途中に通信が失敗した場合は完了件数を表示し、未完了の相手の選択を残します。ホスト自身は一覧や一括操作の対象に含めず、既存のサーバー側の認可を通して設定を反映します。

## PowerPoint読み込み

「ファイル」→「開く」で.pptx（25MB・100ページまで）を選択すると、元の順に横へ並べます。文字・埋め込みPNG/JPEG/WebP/GIF画像・基本図形を編集できます。縦横比は16:9内に収めます。テーマやマスターから継承する書式、グループ、表、グラフ、回転、動画、アニメーションは完全には再現できません。読み込み後は表示を確認してください。パスワード付きファイルと旧.pptは対象外です。処理はブラウザ内で完結し、保存はJSON形式です。

## アンケート（v0.63.0）

クラウドで共有中の作品では、画面ツールバーの「フォーム」から質問と回答を管理できます。ホストは単一選択・複数選択（2〜10項目）・記述式の質問を下書きとして作成し、「受付を開始」で参加者へ公開します。「受付を終了」で回答を確定し、必要なら再開できます。作品の参加者は閲覧のみの権限でも回答でき、受付中は1人1回答を変更できます。未承認・削除された参加者はアクセスできません。

他の参加者の回答と集計結果はホストだけが確認できます。ホストが「集計結果をスライドに挿入」を押すと、現在のページの右に集計用の列を挿入します。選択式は編集可能な棒グラフ、記述式は長い回答も複数ページに分けた文章です。**スライドへ挿入した結果・記述回答は参加者にも見えます。** 挿入した結果はその時点のスナップショットで、回答が変わっても自動更新されません。スライド挿入は通常の取り消しに対応します。

1作品30アンケート、1アンケート500人、質問200文字、記述回答2000文字までです。作成後の質問・選択肢は変更できません。削除するとその質問の回答も削除され、元に戻せません。ホストは回答者名・メールアドレス・最新の回答と回答日時を確認できます（v0.65.0）。参加者には他の人の回答を返さず、挿入スライドに回答者情報を含めません。「回答結果をCSV保存」で選択中の質問を1人1行、UTF-8 BOM付きで保存できます。CSVには質問・形式・氏名・メール・回答・日本時間の日時と選択肢別0/1列を含みます。既存の回答も対象です。質問と回答はクラウド側の専用領域へ保存し、JSON・完全バックアップ・保存した版には含まれません。残したい結果はスライドに挿入してから保存してください。ホストへの集計表示は数秒ごと、受付中の件数は最大約12秒で更新されます。

## スライド内アンケート（v0.64.0）

ホストはツールバーの「フォーム」から、受付を開始済みの質問を選び、「このアンケートをスライドに配置」を押せます。現在のページに質問と回答欄が配置され、編集画面で入力欄以外をドラッグして位置を変え、枠の辺・四隅でサイズ変更できます。回答欄の内側では回答操作が優先されます。

参加者はスライドの編集・閲覧画面、発表画面、ホストによる集合画面の中で直接回答できます。選択式・記述式は従来と同じ質問・集計につながり、複製して複数のページに置いても1人1回答です。受付終了時は自分の保存済み回答を表示し、変更できません。集計・他人の回答は部品の中に表示しません。

サムネイルや印刷は質問・選択肢のプレビューです。JSON・バックアップには元の共有作品と質問への参照・質問のプレビューだけを保存し、回答データは含みません。ローカルで開いたファイルや別の共有作品へのコピーでは質問を表示するだけで、元のアンケートへ自動アクセスしません。元の共有作品で開くと回答機能が有効になります。削除済み・未公開・接続確認中の質問には回答できません。

## ワークシート（v0.66.0）

右下の「ワークシート」から、共有作品のホストが複数の入力欄を持つワークシートを作成できます。「理由と工夫」「セルフチェック」「ふり返り」「改善プラン」「自由に作成」のひな形を選び、タイトル・説明・セクション見出し・項目名・入力例を編集します。記述欄、チェック欄、単一選択、複数選択に対応し、項目の追加・削除・並べ替え、2列／全幅の配置を選べます。チェック欄はチェックした数を自動表示します。1件40項目、1作品30件、1件500人、記述欄は各2000文字までです。

下書きを作成して「受付を開始」し、「このワークシートをスライドに配置」で現在のページへ配置します。部品全体の移動・サイズ変更は既存のスライド編集と同じです。教材の図や説明などは通常のスライド要素と組み合わせて編集できます。部品内は長い内容をスクロールして入力します。作成後は項目を固定し、変更する際は新しいワークシートを作成します。

参加者は閲覧権限でも、自分のアカウントで編集画面・発表画面・ホストへの集合画面・管理パネルから入力できます。記述は入力停止から約1秒後または入力欄を離れた時、選択・チェックはすぐ自動保存し、受付中は変更できます。途中の未入力・未チェックの状態も保存します。ホストは参加者別の最新結果を確認し、「入力結果をCSV保存」で全項目を1人1行にまとめて保存できます。CSVは日本語対応のUTF-8 BOM付きで、氏名・メール・全項目・最終保存日時（日本時間）を含みます。画面の結果は約5秒ごと、CSV保存時は最新データを取得します。

定義と個人の入力は専用領域へ保存します。参加者に他の人の入力結果を返しません。JSON・バックアップ・保存した版・別作品へのコピーには質問の定義と元作品への参照だけが含まれ、個人の入力は含みません。印刷・サムネイルは未入力のプレビューです。元の共有作品以外では入力せず、元の結果へ自動アクセスしません。結果を残す場合はCSVを保存してください。受付終了後は入力を変更できません。ホストがワークシートを削除すると全員の入力も削除され、元に戻せません。

### ワークシートの回答結果（v0.67.0）

ホストがワークシートを選ぶと「回答結果」を直接開きます。「参加者ごと」で氏名・メール・最終保存日時と全項目の回答を確認し、「項目ごとに比較」で同じ問いへの回答を並べて読めます。氏名・メールで検索できます。未入力は明示し、長文の改行を保って表示します。比較表は列幅を確保し、小さい画面では横にスクロールできます。CSVには検索条件に関係なく全員・全項目を保存します。「自分で入力」と「設定・内容の確認」は専用の切替にまとめ、削除操作は設定内に配置しました。

### 全項目の一覧と列固定（v0.68.0）

「全項目を一覧」で、全項目を横に並べて確認できます。左端の氏名・メールと右端の最終保存日時を固定し、中央の回答欄だけを横にスクロールできます。各回答列は280px以上の幅を確保し、長文は改行して表示します。縦スクロール時には項目名の見出しも固定します。参加者ごとの詳細表示・検索・全員のCSV保存にも対応します。

### アンケート・ワークシートの共通画面（v0.69.0）

どちらのボタンから開いても、同じ広いモーダル内で「アンケート」「ワークシート」のタブを切り替えられます。保存済み項目がある場合は先頭の項目を自動選択し、すでに選んだ項目や作成・入力途中の内容はタブ切替中も保ちます。方向キー・Home・Endでもタブを切り替えられ、Escapeで閉じて元のボタンに戻れます。

### 集計グラフの自動更新（v0.70.0）

選択式アンケートの「集計結果をスライドに挿入」で、元のアンケートと連動するグラフを配置します。ホストが明示的に人数・選択肢ごとの件数を参加者へ公開し、回答の追加・変更を約3秒ごとに反映します。回答者名・メール・個別の選択内容・記述回答を集計APIから公開しません。ホストが画面を閉じている場合も、閲覧中の参加者自身が最新の共有集計を取得します。

以前挿入したグラフは、そのページを開き、アンケート画面で元の質問を選んで「このページの既存グラフを連動」を一度実行してください。選択肢の数・ラベルが一致するグラフを対象とし、候補が複数ある場合はグラフを選択してから実行します。「グラフの自動更新・集計共有を停止」で共有集計の取得を止められます。連動中も色・種類・表示設定を変更でき、項目名と件数は自動更新します。

元の共有作品で開いている間だけ更新します。別作品へのコピー・元のアンケート削除・集計共有停止・接続確認中・オフラインでは保存済みの数値を表示します。JSON保存時は取得済みの最新集計を表示用の値として残し、参照と集計値以外の回答データは埋め込みません。バックアップや過去の版にはスライドに記録した時点の値が含まれます。記述回答の集計スライドは挿入時点の内容を保持します。

### 共通の入口（v0.70.1）

右下の「アンケート・ワークシート」ボタンから共通画面を開きます。同じ作品を開いている間は前回のタブを保ち、モーダル内で切り替えられます。

### フォームの入口（v0.71.3）

アンケート・ワークシートの入口はツールバーの「フォーム」に統一しました。右下の独立したボタンはありません。マップ・ページ編集・発表・ホスト追従画面で利用でき、前回のタブを開きます。閲覧専用の参加者も、自分の回答入力と公開された回答スライドの確認に使えます。フォームの作成・管理・CSV出力はホスト用です。
