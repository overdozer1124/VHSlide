# 指導書・教科書から VHSlide の授業スライドを作る

**先生への回答・報告・質問は、すべて日本語で書く。**

## 成果物

作るのは VHSlide の作品ファイル（`.vhslide.json`）、またはその元になるレッスン仕様JSON（先生が変換ページで `.vhslide.json` にする）。ほかの形式のスライド（スライド作成機能、プレゼンテーションのファイル、HTML）は作らない。「スライドを作って」と頼まれたときも、下の手順で作る。生徒が VHSlide の中で回答を入力する入力欄とワークシートは、レッスン仕様からしか作れない。

入力（指導書・教科書の画像やPDF）から授業を設計し、生徒への問いとワークシートの入力欄を含む VHSlide の作品ファイルを作る。
ページの組み立ては `scripts/build_deck.py`（Python の標準ライブラリだけで動く）が行う。あなたは **授業の設計（レッスン仕様JSON）と図** に集中する。座標を手で計算して VHSlide のJSONを直接書かない。

参照するファイル（このSKILL.mdと同じフォルダ）：
- `references/spec-format.md`：レッスン仕様の書き方（ページの種類・キー）。**書く前に必ず読む。**
- `references/design.md`：トーン・キャラクターの一覧と見た目の原則
- `references/vhslide-features.md`：VHSlide の機能（対応版 {{VHSLIDE_VERSION}}）
- `references/examples.md`：完成例（1時間の授業）とページの型の例

## 0. 最初に1回だけ確認する（1つのメッセージにまとめ、番号付きの選択肢で聞く）

先生がすでに指定していれば聞かずに従う。

1. 配置：`lesson-rows`（1行＝1単位時間。左から右へ進み、次の時間は下の行。既定）／`phase-grid`（導入・展開・まとめを縦に並べる）
2. トーン：`references/design.md` の一覧から、教材に合う2〜3個をすすめる。言葉で希望されたら（例：「食事が楽しくなる感じ」）近いプリセットを `base` にして色を上書きする。
3. キャラクター：一覧から教科に合うものをすすめる（なしも可）。
4. 複数時間の単元なら、何時間目まで作るか。

## 1. 教材を読み、授業を設計する

指導書から、学習目標・時数・学習の流れ（導入／展開／まとめと分数）・発問・指導のポイントと留意点・資料（図・表・グラフの数値）・板書例・評価の観点を抜き出す。

- **問いを中心に組む。** 活動ごとに「生徒への問い（question・fields・quiz）→ 解説（cards・flow・points・statement）」の対にする。問いのページには必ず入力欄を置く。
- **ページの型を混ぜて単調にしない。** 同じ kind を3枚続けない。数値・結論を印象づける → `statement`、2つの違い → `compare`、順番のある内容 → `steps`、全員参加の確認 → `quiz`。場面の切り替わりには区切りページ（`section`）が自動で入る。
- 入力欄は1時間に5〜10個。選択式（single・multiple）には `"reason": true`（理由欄）、全体で共有したいものには `"public": true`（集計公開）。調べ学習・観察・作品紹介など画像があると伝わる問いには `"type": "drawing"`（画像・手描き）の欄を、説明の text 欄と横に並べる。
- **ルーブリックを必ず付ける。** 各時間の `rubric` は観点×A/B/Cの3段階。1行目は指導書の評価規準（B＝評価規準の文言、A＝質的に高い姿、C＝努力を要する状況）。観点は2〜4個、1マス50字程度まで、生徒に分かる言葉で。導入の学習課題の直後に `{"kind":"rubric"}`、まとめの最後のふり返りの前に `{"kind":"rubric","selfCheck":"public"}` を置く。
- 指導書の「指導のポイント」「留意点」「評価」「予想される反応」は各ページの `notes`（発表者ノート）に入れ、生徒の画面には書かない。
- 資料の数値は教材から正確に写す。読み取りに自信のない数値は報告で「照合してほしい数値」として挙げる。
- 実在の人物名・写真は載せない。教科書の図はそのまま写さず、数値から作り直す。
- 紙のワークシートを「スライドにして」と頼まれたら、`form` で入力欄を座標配置して1ページに組み直す（A4縦→横長は列や上下の帯に組み替え、項目名・順序は原本どおり、入力欄の高さは44以上）。
- 1ページの文章は短く（1つの枠に3行まで）。長い説明はページを分ける。

## 2. 図を作る

- 棒・折れ線・円のグラフは `chart`（VHSlide で編集できる）。1ページに2つまで、ラベルは6字以内を目安に。
- それ以外の図（比較図・流れ図・模式図）は、コード実行で matplotlib または Pillow を使い PNG を作業フォルダに保存し、`image` にそのファイル名を書く。**日本語の文字は図に描かない**（フォントが無く文字化けする）。図は形・矢印・数字だけにし、言葉は `form` の `text` として図の上に重ねるか、ページの見出し・カードに書く。
- 先生が渡した写真・挿絵を使うときは、そのファイルを作業フォルダに置いて `image` にファイル名を書く。
- キャラクターと背景の装飾は自動で入る（問い＝考える顔、解説＝ひらめき、表紙＝うれしい顔）。

## 3. 仕上げる（どちらか）

コード実行は回数に上限があるので、教材の画像を細かく切り分けて何度も読むことはしない。仕様は一度で書き上げる。

### A. 作業フォルダに build_deck.py がある場合（先生がこのスキルの zip をチャットに添付したとき）

1. 最初の1回で、作業フォルダの zip を展開して `scripts/build_deck.py` を探す。見つからなければ、すぐ B に進む（何度も探さない）。
2. レッスン仕様は **JSON の文字列のまま** ファイルに書く。Python の辞書として書かない（`true`・`false`・`null` がエラーになる）。

```python
spec_text = r'''{ ...ここにレッスン仕様のJSON... }'''
import json, subprocess
json.loads(spec_text)  # 文法の確認
open("lesson.spec.json", "w", encoding="utf-8").write(spec_text)
print(subprocess.run(["python3", "vhslide-lesson/scripts/build_deck.py", "lesson.spec.json", "単元名.vhslide.json"], capture_output=True, text=True))
```

3. 「作れませんでした：…」と出たら、理由を読んで仕様を直し、もう一度実行する。「※」で始まる注意は読んで必要なら直す。
4. 成功したら、`.vhslide.json` を先生がダウンロードできるファイルとして渡す。

### B. build_deck.py が無い場合（ふつうはこちら）

1. レッスン仕様JSONを ```json のコードブロック1つで出す（コメント・末尾のカンマのない正しいJSON）。長いときは、1時間ずつ ```json ブロックを分けてよい（2つ目からは {"lessons": [ … ]} だけ）。
2. 先生に「VHSlide 授業スライド変換」ページ（先生の手元にあるHTMLファイル）を開き、返答をそのまま貼って「作成する」→「ファイルを保存」するよう案内する。画像ファイルを使う仕様なら、その画像も変換ページで選ぶよう伝える。
3. 変換ページのエラー文を貼られたら、直した仕様を全体もう一度出す。

### 文字があふれないために

- ルーブリックの1マスは45字まで。表のセルは1行に収まる長さにし、セルの中で改行しない（見出し行だけ改行してよい）。
- 表の横に入力欄を置くときは、表の列を4列までにする。

## 4. 先生への報告

- 構成（行と主なページ）、入力欄の一覧、照合してほしい数値を箇条書きで。
- 使い方：VHSlide の「ファイル → 開く」でファイルを読み込み、**クラウドに保存**すると入力欄が使える。授業コンソールで回答一覧・集計・生徒のスライドを見られ、「全員を集合 → 発表する」で生徒の画面がスライドだけになり入力できる。
- 文字の見切れは自動で文字の大きさを調整しているが、画面での確認はできないので、VHSlide で「発表する」を押したときの表示チェックで確かめるよう一言添える。
